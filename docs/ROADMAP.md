## 3. M2 地图：范围与接缝

M1 现在的生成器（`src/Plugins/core.basic/MapGen.cs`）只跑了 §3.7 六步里的两步：

| §3.7 步骤 | M1 | M2 要做的事 |
|---|---|---|
| 1 高度图 | ✅ | 换成真正的多倍频噪声（现在是盆地 + 外环高地），仍不许用 `Pow/Exp/三角` |
| 2 地表分类 | ✅ 五类地表按高度/坡度分 | 接上 §3.2 表余下的行 |
| 3 河流 | ⛪ | §3.3 的「地块边上的有向图」：水系要能决定水利系数 1.15 与河运 |
| 4 形胜识别 | ⛪ | §3.4 十二种，程序化识别。**验收靠它**：同形胜在 20 张图里人工可认 |
| 5 门槛资源 | ⛪ | §3.5（不是第 6 种商品） |
| 6 图层落盘 | 🟡 | `core.basic` 已注册 `terrain/owner/agriculture` 三层（`BasicPlugin.cs:86-88`），M2 补 §3.9 的 4–5 层 |

必须先动接口而不是先动算法的两件事：

1. **地图形状**。现在是半径制六边形（`MapGen.DefaultRadius = 4` → 61 格，
   半径存全局字段 `config.mapRadius`，1–12 越界即拒建图），
   §3.7 与 §13.1 要的是 **32 × 20**，即轴向坐标下的矩形。这一步会改 `MapGen.Bootstrap` 的遍历范围
   与 `hex.q.r` 的 id 约定，也要改 GodotShell 的渲染与拾取（smoke 现在报「拾取 183/183 命中」）。
2. **`CoreInfo.MapGenVersion` 必须 +1 并写进存档**（`Simulation.cs:228` 已经在写 `meta.mapGenVersion`）。
   旧种子会长出新地图，这是 §3.7 末行与 §10.6 的明写要求，不是回归。
3. **选址规则跟着改**。`Siting.BestTownSite` 现在是
   `score = Σ 半径 2 内无主格的 Y粮 × 100 − 已开发格数`，平票取 hex id 的 ordinal 最小者；
   形胜/资源/河口进来时**只改这个函数**，命令面与 `scripts/*.txt` 都不用动（这是它当初存在的全部理由）。

性能验收（32×20 < 1 s）现在**测不到**：地图生成是 `RegisterBootstrap`，跑在 `Bootstrap()` 里，
不在 15 步的任何一步上，所以 `sim run --steps` 的分步耗时表里看不到它。
M2 的第一件事是给 `sim map` 加一行 bootstrap 计时（或写进 `sim check`），否则验收标准无从判定。

**结论：切片验收要等 M5–M6**。现在能演示的是「地图 → 建国 → 建城 → 开荒 → 攒粮 → 缺粮 → 造反」
