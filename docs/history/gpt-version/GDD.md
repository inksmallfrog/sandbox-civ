# 《群邦纪元》完整游戏设计与开发总纲

**文档版本：** GDD 0.1  
**项目阶段：** 项目立项 / 系统设计  
**目标平台：** Windows PC，后续扩展 Linux、macOS  
**目标发行平台：** Steam  
**游戏模式：** 单人、AI 对战、本地热座、在线联机  
**引擎：** Godot 4.7.2 Stable  
**主要开发语言：** GDScript  
**核心架构：** 插件化、数据驱动、确定性回合结算

# 第一部分：游戏核心设计

## 1. 游戏世界与基本概念

### 1.1 游戏背景

游戏发生在一个随机生成的世界。

世界由多个地区、地形、资源和独立城镇组成。不同城镇在地理条件、人口组成、生产能力、文化传统方面具有差异。

玩家以国家的身份参与世界发展，可以：

- 管理自己的城镇。
- 建设新的城镇。
- 与其他国家争夺土地和资源。
- 吸纳独立城镇。
- 发展国内经济与国际贸易。
- 研究技术。
- 发展宗教、文化和军事。
- 招募和任命各种名人。
- 制定国家政策。
- 与其他国家结盟、竞争或战争。

世界中的其他国家由 AI 或其他玩家控制。

**特别设计：国家并不等于城镇，城镇也不一定属于国家。**

一座城镇可以是：
1. 国家直属城镇。
2. 拥有一定自治权的附属城镇。
3. 向其他国家纳贡的属国城镇。
4. 完全独立的城镇。
5. 被军事占领但尚未完成正式整合的城镇。

这使玩家拥有除征服以外的扩张方式。

### 1.2 游戏时间

采用年度回合制。

每回合代表一年，内部包含四个季节阶段：

- 春季：播种、建设、人口流动。
- 夏季：农业生产、贸易、军事行动。
- 秋季：收获、市场结算、财政收入。
- 冬季：人口消费、社会矛盾、年度统计。

玩家每年制定一次主要政策和行动计划，系统再根据四季依次执行。

好处是：

1. 玩家不用频繁操作每个月的经济细节。
2. 农业季节性、灾害、贸易仍然能够产生丰富变化。
3. AI 和联机回合结算比较容易维护。
4. 玩家可以清楚比较每年的发展成果。

### 1.3 核心游戏循环

完整游戏循环：

**探索世界 → 建立城镇 → 发展阶级 → 形成经济 → 制定政策 → 招募人才 → 发展科技 → 扩张国家 → 外交竞争 → 战争与合作 → 文明演变。**

每年结束后，游戏给出一份年度报告。

年度报告至少包含：

- 人口变化。
- 各阶级变化。
- 商品供需和价格变化。
- 城镇收入与支出。
- 国家财政情况。
- 科技进度。
- 社会满意度。
- 名人个人动态。
- 外交关系。
- 军事行动结果。
- 本年度重大随机事件。

## 2. 世界地图与地块系统

### 2.1 地图基本结构

使用六边形网格（Hex Grid）。

每个地块拥有以下属性：

| 属性 | 说明 |
|---|---|
| 坐标 | 六边形轴向坐标 q、r |
| 地形 | 平原、山地、森林等 |
| 地貌 | 河谷、盆地、三角洲等 |
| 海拔 | 影响河流和军事移动 |
| 气候 | 温度与降水 |
| 肥沃度 | 影响农业 |
| 基础产出 | 地块资源潜力 |
| 特产资源 | 铁矿、金矿、盐等 |
| 通行条件 | 军队、商队和居民移动 |
| 控制权 | 国家、城镇或独立状态 |
| 地块设施 | 农田、道路、矿场、堡垒等 |

不能将地形、资源、地貌全部做成互相排斥的类型。

正确的结构是：

**地形 + 地貌特征 + 资源 + 人工设施 + 地形边界效果。**

例如：

一块丘陵可以同时具有森林、铁矿、河流边界和道路。

这样地图能够产生非常丰富的组合。

### 2.2 地块地形分类

建议第一版实现以下 16 种基础地形。

| 地形 | 主要特点 | 主要用途 |
|---|---|---|
| 平原 | 地势平缓 | 农业、建设 |
| 草原 | 适合放牧 | 畜牧业 |
| 肥沃平原 | 农业产出高 | 粮食中心 |
| 丘陵 | 起伏较大 | 矿业、军事防御 |
| 高山 | 高海拔 | 防御、矿产 |
| 密林 | 木材丰富 | 林业、狩猎 |
| 雨林 | 生物资源丰富 | 特产、药材 |
| 沼泽 | 通行困难 | 渔业、药材、防御 |
| 沙漠 | 缺水、农业困难 | 商路、矿产 |
| 绿洲 | 沙漠中的水源 | 城镇、贸易 |
| 荒漠草原 | 降水较少 | 放牧 |
| 温带森林 | 木材与农业兼具 | 混合经济 |
| 苔原 | 寒冷 | 狩猎、皮毛 |
| 冰雪地 | 极端寒冷 | 战略屏障 |
| 火山地 | 火山活动和矿产 | 高风险资源区 |
| 海岸浅滩 | 靠近海洋 | 港口、渔业 |

### 2.3 水域系统

水域分成三种类型：

**第一种：河流**

河流不应简单地作为普通地块。

建议在六边形地块之间设置河流边界数据。

例如：

- 一条河流经过几个地块。
- 某些地块之间存在河流边界。
- 河流两岸可以建设桥梁。
- 军队渡河需要额外行动力。
- 河流沿岸可以建设灌溉系统。
- 河道可以提高贸易运输效率。

这样可以自然形成重要的渡口和战略要地。

**第二种：湖泊**

湖泊是不可普通陆地通行的水域地块。

效果：

- 提供淡水。
- 提供渔业资源。
- 可以形成湖畔城镇。
- 湖区能够形成内河运输路线。
- 湖泊周边更容易出现肥沃平原。

**第三种：海洋**

海洋分成：

- 近海。
- 深海。

近海支持渔业、港口和早期海运。

深海需要更高级的航海技术。

### 2.4 特殊地貌组合

这是地图最值得开发的部分。

不要仅生成随机山地和平原，而应该让地图形成具有战略意义的地貌结构。

| 地貌 | 生成规则 | 战略意义 |
|---|---|---|
| 河流盆地 | 多条河流流入低洼区域 | 农业与人口中心 |
| 山地盆地 | 四周高地，中间低地 | 易守难攻 |
| 山谷 | 两侧山脉夹着狭长平原 | 战略通道 |
| 山口 | 两个山地之间的低地 | 军事关隘 |
| 三角洲 | 大河入海，分散成多条支流 | 农业、港口、贸易 |
| 湖泊群 | 多个相连湖泊 | 淡水与运输 |
| 半岛 | 三面环海 | 海军基地 |
| 海峡 | 两块陆地间狭窄水域 | 海军战略 |
| 群岛 | 多个海岛组成 | 海上贸易 |
| 高原 | 大面积高海拔地区 | 防御、矿业 |
| 绿洲走廊 | 沙漠中的连续水源 | 陆上商路 |
| 沿海平原 | 海岸与山地之间的平原 | 港口与人口集中 |

这些组合应当对 AI 和玩家同样具有战略价值。

### 2.5 资源分布

建议分为四类。

**基础资源：**

- 粮食。
- 木材。
- 石材。
- 矿石。

**加工资源：**

- 金属。
- 工具。
- 纺织品。
- 陶器。
- 纸张。
- 药品。
- 武器。

**特殊资源：**

- 盐。
- 马匹。
- 宝石。
- 香料。
- 药草。
- 鱼类。

**非实体资源：**

- 金钱。
- 知识。
- 信仰。
- 文化。

非实体资源不应与普通商品混在同一个库存逻辑中。

### 2.6 地块产出

地块本身只提供资源潜力，不应该自动生产无限商品。

真正的产出必须依赖人口和设施。

例如：

肥沃平原：

- 基础农业潜力：高。
- 建造农田后提高生产效率。
- 分配农民人口后形成实际粮食产出。

森林：

- 基础木材潜力：高。
- 建造伐木场。
- 分配工人后生产木材。

这样可以避免没有人口却自动产生资源的情况。

### 2.7 地图随机生成算法

建议使用固定随机种子，并将生成过程分成六个阶段：

1. 生成大陆轮廓。
2. 生成海拔和山脉。
3. 根据海拔生成河流和湖泊。
4. 根据温度和降水生成地形与气候。
5. 根据地质生成矿产和特殊资源。
6. 检查玩家起始位置，调整公平性。

随机地图必须遵守：

- 起始区域至少有基本粮食来源。
- 每个玩家附近存在至少一种战略资源。
- 不保证所有玩家拥有完全相同的资源。
- 重要资源应该形成争夺价值。
- 地图种子必须可以复现同一张地图。
- 地图生成算法升级时必须增加版本号，保证老存档可识别。

# 第二部分：城镇系统

## 3. 城镇系统总体结构

城镇是整个游戏真正的核心。

国家只是政治和战略管理层，城镇才是人口、经济、阶级和社会活动发生的地方。

每个城镇都应该是一个完整、独立的数据实体。

城镇包含：

1. 人口系统。
2. 阶级系统。
3. 经济系统。
4. 城镇财政系统。
5. 行政管理系统。
6. 宗教系统。
7. 科技系统。
8. 军事系统。
9. 文化系统。
10. 城镇政治系统。

这些系统通过统一的城镇状态进行交互，但各自拥有独立逻辑。

### 3.1 城镇基础属性

| 属性 | 说明 |
|---|---|
| 城镇等级 | 村庄、城镇、城市、大都市 |
| 总人口 | 实际人口数量 |
| 阶级组成 | 八种阶级的人口 |
| 住房容量 | 能够容纳的人口 |
| 食物储备 | 粮食安全程度 |
| 城镇库存 | 商品库存 |
| 城镇财政 | 城镇自主资金 |
| 社会稳定 | 居民对当前环境的接受程度 |
| 行政效率 | 命令执行能力 |
| 城镇繁荣度 | 综合发展状态 |
| 文化特色 | 城镇形成的历史文化 |
| 信仰结构 | 居民宗教构成 |
| 所属国家 | 可以为空 |
| 自治程度 | 国家对城镇的控制强度 |

### 3.2 城镇人口

人口建议采用抽象人口单位。

**一个人口单位代表 100 名实际居民。**

例如：

- 100 人 = 1 单位。
- 1,000 人 = 10 单位。
- 10,000 人 = 100 单位。

内部统一采用整数或定点数进行计算，避免显示与计算产生大量小数问题。

人口由以下条件决定：

- 食物供应。
- 住房。
- 医疗。
- 就业。
- 生活满意度。
- 社会稳定。
- 外来移民。

人口变化主要来自自然增长、迁移和阶级转化。

不要将人口增长设计成单纯每回合固定增加百分比。

## 4. 八大人口阶级

八大阶级是本游戏最重要的设计。

每种阶级都是独立系统。

但为了避免代码复杂，应统一采用相同的基础接口：

- 人口数量。
- 工作岗位。
- 商品需求。
- 生产能力。
- 收入水平。
- 满意度。
- 阶级影响力。
- 阶级特有属性。

八个阶级只需要通过数据和各自的少量规则实现差异。

### 4.1 农民阶级

**定位：基础粮食与农业生产者。**

解锁条件：游戏初始存在。

消费：

- 粮食。
- 基础工具。
- 生活用品。

产出：

- 粮食。
- 纤维。
- 畜产品。
- 农业原材料。

特殊能力：

- 农业生产。
- 土地利用。
- 灌溉设施维护。
- 粮食储备管理。

农民阶级影响因素：

- 土地肥沃度。
- 农业技术。
- 土地占有制度。
- 粮食价格。
- 农业税收。
- 自然灾害。

农民壮大有利于粮食供应，但如果农业人口比例过高，也可能导致工业和商业发展滞后。

### 4.2 工人阶级

**定位：工业生产与城市建设。**

解锁条件：

- 存在工坊或工业设施。
- 城镇具备基本工具供应。
- 达到对应生产技术。

消费：

- 粮食。
- 住房。
- 工具。
- 纺织品。

产出：

- 金属。
- 工具。
- 纺织品。
- 陶器。
- 武器。
- 建筑材料。

特殊能力：

- 工业生产。
- 建筑施工。
- 原材料加工。
- 生产效率提高。

工人阶级越发达，城镇越容易进入工业化阶段。

但是工人数量增长过快，可能导致：

- 粮食需求增加。
- 住房不足。
- 工资压力。
- 工人政治影响力增加。
- 生产过剩和失业。

### 4.3 商人阶级

**定位：市场、商品流通和贸易。**

解锁条件：

- 建立市场。
- 城镇出现一定商品剩余。
- 存在基本贸易条件。

消费：

- 粮食。
- 住房。
- 奢侈品。
- 商业服务。

产出：

- 商业流通效率。
- 贸易收入。
- 市场服务。
- 国际贸易能力。

商人不直接创造商品。

他们的价值在于连接生产者和消费者，让商品能够跨阶级、跨城镇、跨国家流通。

特殊能力：

- 改善市场匹配效率。
- 降低部分交易成本。
- 开启贸易路线。
- 提高商品流通量。
- 提供商业情报。

商人壮大可能带来繁荣，也可能带来财富集中和政治影响力过大。

### 4.4 官僚阶级

**定位：行政管理和国家制度执行。**

解锁条件：

- 建造行政建筑。
- 城镇达到一定人口。
- 解锁城镇管理制度。

消费：

- 粮食。
- 住房。
- 纸张。
- 基础奢侈品。

产出：

- 行政点数。
- 管理效率。
- 税收征集能力。
- 政策执行能力。
- 建筑规划能力。

特殊能力：

- 提高行政效率。
- 降低腐败损失。
- 提高税收征收率。
- 执行国家命令。
- 管理人口和社会事务。

官僚过少时，国家的命令无法有效执行。

官僚过多时，会形成行政成本和官僚利益集团。

### 4.5 祭司阶级

**定位：宗教、信仰与社会精神秩序。**

解锁条件：

- 建造神庙或宗教场所。
- 城镇存在宗教传统。
- 达到相应文明条件。

消费：

- 粮食。
- 住房。
- 宗教用品。
- 部分奢侈品。

产出：

- 信仰点数。
- 宗教影响力。
- 社会凝聚力。
- 宗教教育与传统维护。

特殊能力：

- 提高信仰影响力。
- 降低部分社会矛盾。
- 举办宗教活动。
- 提供宗教合法性。
- 传播宗教。

祭司阶级可能支持政府，也可能与政府发生冲突。

### 4.6 学者阶级

**定位：知识、科研与技术进步。**

解锁条件：

- 建立学校或研究机构。
- 解锁书写、教育或相应知识技术。

消费：

- 粮食。
- 住房。
- 纸张。
- 工具。
- 部分奢侈品。

产出：

- 科研点数。
- 技术创新。
- 科学文化。
- 行政知识。
- 教育能力。

特殊能力：

- 提高科技研究速度。
- 开发新生产方法。
- 提高部分建筑效率。
- 产生技术突破事件。

学者阶级的核心价值在于帮助文明实现技术跃迁。

### 4.7 军人阶级

**定位：国家军事力量。**

解锁条件：

- 建立军营或军事训练设施。
- 国家具备征兵或常备军制度。

消费：

- 粮食。
- 武器。
- 装备。
- 住房。

产出：

- 军事训练能力。
- 城镇防御。
- 军事组织能力。
- 军事人力。

特殊能力：

- 训练军队。
- 维护城防。
- 提高军队士气。
- 参与军事行动。
- 产生军事人才。

军人阶级壮大能提升国家安全，但常备军规模过大也会造成财政压力和军队政治影响力上升。

### 4.8 文艺家阶级

**定位：艺术、文化和社会精神表达。**

解锁条件：

- 建立文化建筑。
- 城镇具备一定教育或经济基础。
- 解锁文化发展条件。

消费：

- 粮食。
- 住房。
- 文化用品。
- 奢侈品。

产出：

- 文化点数。
- 城镇文化影响力。
- 艺术作品。
- 国家声望。
- 旅游和文化吸引力。

特殊能力：

- 创作艺术作品。
- 举办节庆。
- 发展城市文化。
- 传播国家文化。
- 提升文化认同。

文艺家不是单纯增加一个文化数值，他们还负责创造可以影响国家声望和外交关系的文化成果。

---

## 5. 阶级解锁与人口流动

八个阶级不应在游戏开始时全部存在。

建议采用条件解锁。

| 阶级 | 主要解锁条件 |
|---|---|
| 农民 | 初始 |
| 工人 | 工坊、工具供应、生产技术 |
| 商人 | 市场、商品剩余、贸易条件 |
| 官僚 | 行政建筑、城镇规模、管理制度 |
| 祭司 | 宗教建筑、信仰传统 |
| 学者 | 学校、书写技术 |
| 军人 | 军营、征兵制度 |
| 文艺家 | 文化建筑、文化技术 |

解锁不等于自动生成大量人口。

只代表城镇已经具备该阶级形成的条件。

### 5.1 人口转化逻辑

使用就业机会和生活吸引力共同决定阶级增长。

每个阶级计算一个吸引力：

`阶级吸引力 = 收入水平 + 就业机会 + 社会地位 + 福利待遇 - 生活成本 - 风险`

使用 0～100 分表示。

每年：

1. 检查当前阶级是否存在未满足的岗位需求。
2. 检查其他阶级人口是否具备转化条件。
3. 根据吸引力差异计算人口流动。
4. 限制每年最大转化比例。
5. 处理人口增长、死亡和迁移。

建议初期限制每年单个阶级转入人口不超过城镇总人口的 2%，具体数值通过测试调整。

这样不会出现一个阶级突然吞掉整个城镇人口的情况。

### 5.2 阶级满足度

每个阶级拥有独立满意度。

范围：0～100。

满意度由以下项目组成：

- 生活必需品满足率。
- 工资与收入。
- 税收负担。
- 就业情况。
- 政治代表权。
- 社会地位。
- 国家政策。
- 安全情况。

状态划分：

| 满意度 | 状态 | 主要效果 |
|---|---|---|
| 80～100 | 满意 | 效率与忠诚增加 |
| 60～79 | 稳定 | 正常运作 |
| 40～59 | 不满 | 效率下降 |
| 20～39 | 激化 | 抗议、怠工、逃税风险 |
| 0～19 | 危机 | 暴动、叛乱、人口外逃风险 |

必须避免单一回合满意度下降就立刻发生暴动。

建议连续两个年度处于危机状态后，才允许触发严重事件。

---

## 6. 阶级矛盾系统

这是整个城镇系统最有特色的部分。

不建议直接创建八个阶级之间的 28 种复杂矛盾关系。

第一版只采用四个主要矛盾指标：

1. 财富分配。
2. 商品与生活成本。
3. 税收与政策负担。
4. 政治权力分配。

每个阶级拥有自己的利益偏好。

例如：

| 阶级 | 主要诉求 |
|---|---|
| 农民 | 土地、粮食价格、农业税 |
| 工人 | 工资、就业、住房、工作环境 |
| 商人 | 贸易自由、低关税、市场效率 |
| 官僚 | 行政预算、管理权限、职业地位 |
| 祭司 | 宗教权利、信仰自由、社会影响力 |
| 学者 | 科研预算、教育自由、知识传播 |
| 军人 | 军费、装备、地位、军队保障 |
| 文艺家 | 艺术资助、表达空间、文化地位 |

### 6.1 阶级矛盾计算

每个阶级计算：

`阶级压力 = 生活压力 + 政策压力 + 权力落差 + 财富不满`

最终形成城镇内部的矛盾指数。

矛盾指数越高，出现以下情况的风险越高：

- 阶级抗议。
- 罢工。
- 逃税。
- 资本外流。
- 官僚抵制。
- 宗教冲突。
- 军队干预。
- 城镇自治诉求。

### 6.2 矛盾事件的处理

矛盾不是只用负面数值表示。

当矛盾上升时，应当向玩家提供政治选择。

例如：

工人阶级要求提高工资。

玩家可以：

- 提高工人工资保障。
- 降低工人税收。
- 增加公共住房。
- 允许工人组织。
- 暂时忽视。
- 采用强制手段。

这些选择会影响不同阶级。

提高工资可能增加工人满意度，但降低企业利润，影响商人和城镇财政。

这才是有趣的策略决策。

# 第三部分：经济系统

## 7. 经济系统总体设计

采用三级经济循环：

1. 城镇经济内循环。
2. 国家经济内循环。
3. 国际经济外循环。

最重要的是：**金钱和商品必须遵循真实的流动方向，不能无缘无故产生。**

生产会创造商品。

贸易会转移商品。

消费会消耗商品。

税收会转移资金。

投资会消耗资金并转化为设施和生产能力。

### 7.1 经济资源结构

经济系统分为：

**商品：** 粮食、木材、石材、矿石、金属、工具、纺织品、陶器、纸张、药品、武器、奢侈品等。

**货币：** 用于工资、消费、贸易、投资、税收。

**特殊经济资源：** 知识、信仰和文化。

特殊资源不应直接按照普通商品交易，后期可以通过独立系统实现其转化。

---

## 8. 城镇经济内循环

城镇内循环由四个环节组成。

### 8.1 生产

农民和工人生产商品。

例如：

农民：
- 农田 → 粮食。
- 牧场 → 畜产品。
- 农业设施 → 纤维。

工人：
- 矿场 → 矿石。
- 冶炼厂 → 金属。
- 工坊 → 工具。
- 纺织厂 → 纺织品。

商人不直接生产普通商品，而是负责流通。

### 8.2 市场

城镇建立统一市场。

每个阶级根据人口数量和生活标准产生消费需求。

例如：

| 阶级 | 基础消费 |
|---|---|
| 农民 | 粮食、工具 |
| 工人 | 粮食、纺织品、工具 |
| 商人 | 粮食、住房、奢侈品 |
| 官僚 | 粮食、纸张、生活用品 |
| 祭司 | 粮食、宗教用品 |
| 学者 | 粮食、纸张、工具 |
| 军人 | 粮食、武器 |
| 文艺家 | 粮食、文化用品、奢侈品 |

### 8.3 价格

采用供需决定价格。

简化公式：

`供需差额 = 商品需求量 - 商品供应量`

`价格变化率 = 0.12 × 供需差额 / max(需求量, 供应量, 1)`

`下一期价格 = 当前价格 × (1 + 价格变化率)`

价格每年变化幅度限制在一定范围内，例如上涨或下跌 15%。

价格同时存在上下限，避免无限上涨或者跌到零。

例如：

- 粮食供应过剩，粮食价格下降。
- 粮食短缺，价格上涨。
- 工具供应过剩，工业利润可能下降。
- 某类奢侈品价格上涨，会吸引商人和工人向相关行业转移。

### 8.4 工资与利润

各阶级不能无条件凭空获得金钱。

生产经营单位根据商品销售收入支付：

1. 原材料成本。
2. 工人工资。
3. 设施维护成本。
4. 商业费用。

剩余部分成为企业利润。

商人可以从商品流通、交易服务和贸易差价获得收入。

如果销售收入不足：

- 企业降低工资。
- 企业减少生产。
- 工人失业。
- 阶级满意度下降。
- 城镇经济逐渐收缩。

这样就能自然形成经济周期。

---

## 9. 国内经济循环

国内经济通过各城镇之间的商品流动实现。

每座城镇都有独立市场。

国家市场不是一个无限库存仓库，而是由各城镇市场通过道路、河流、港口和商队网络连接起来。

贸易逻辑：

1. 城镇 A 有商品过剩。
2. 城镇 B 有商品短缺。
3. 计算二者价格差异。
4. 计算运输成本和风险。
5. 检查贸易路线容量。
6. 检查两座城镇的贸易政策。
7. 成交后转移商品和货币。

只有当运输后仍有利润时，商人才能持续经营。

### 9.1 国内市场政策

国家可以制定：

- 全国市场开放。
- 城镇之间贸易限制。
- 特定商品保护。
- 国内关税。
- 国家战略物资征购。
- 公共粮食储备。

国家可以通过这些政策扶持偏远地区，也可能造成商品流通效率下降。

### 9.2 国家财政

国家与城镇使用不同的财政账户。

城镇收入：

- 地方税收。
- 城镇商业收入。
- 城镇设施收入。
- 地方贸易费用。

国家收入：

- 属地上缴税收。
- 国内贸易税。
- 关税。
- 属国贡赋。
- 国家产业收入。

国家支出：

- 官员俸禄。
- 军队维护。
- 城镇建设补助。
- 科研资助。
- 外交支出。
- 国家公共建设。
- 战争费用。

国家不能随意直接拿走城镇所有资金。

必须由税收、征购、法令和其他明确机制完成资金转移。

---

## 10. 国际经济循环

国际贸易发生在不同国家的城镇之间。

核心逻辑与国内贸易相同，但需要额外考虑：

- 国际运输成本。
- 关税。
- 国家关系。
- 战争风险。
- 海盗与劫掠。
- 贸易封锁。
- 国际商品价格。
- 贸易协议。

### 10.1 外贸交易流程

例如：

A 国的城镇拥有大量铁矿。

B 国的城镇拥有大量粮食。

双方可以建立贸易路线：

1. 商人提出贸易需求。
2. 双方检查市场价格。
3. 双方检查库存。
4. 检查贸易路线容量。
5. 计算运输成本和税收。
6. 确定成交数量和价格。
7. 商品运输。
8. 完成结算。

### 10.2 外贸协议

支持：

- 固定数量商品交易。
- 定期贸易合同。
- 贸易关税优惠。
- 战略资源优先购买。
- 贸易禁运。
- 港口通行权。
- 长期商业合作。

贸易关系应该成为外交的重要部分。

---

# 第四部分：国家系统

## 11. 国家系统总体结构

国家是玩家的主要管理对象。

国家不直接经营每一家生产设施，而是通过制度和政策影响城镇。

一个国家包含：

- 国家身份。
- 国家领土。
- 所属城镇。
- 国家财政。
- 国家政策。
- 政治制度。
- 国家科技。
- 国家军队。
- 国家宗教。
- 国家文化。
- 外交关系。
- 官员与名人。

国家的权力取决于：

1. 领土和城镇。
2. 行政管理能力。
3. 军事能力。
4. 经济实力。
5. 人口规模。
6. 科技水平。
7. 外交影响力。

### 11.1 国家与城镇的关系

这是整个系统必须重点实现的地方。

建议通过城镇的 `sovereignty_status` 表示归属状态：

- Independent：独立。
- Core：核心直属。
- Province：普通属地。
- Autonomous：自治城镇。
- Vassal：附属城镇。
- Occupied：军事占领。

国家通过城镇的行政关系产生影响。

例如：

核心城镇：
- 税收上缴比例较高。
- 行政命令容易执行。
- 国家拥有较高管理权。

自治城镇：
- 保留部分地方政策权。
- 国家税收较低。
- 地方满意度相对容易维持。

附属城镇：
- 通过贡赋和军事义务提供收益。
- 保留部分内部管理权。
- 可能发生独立倾向。

独立城镇：
- 拥有独立财政和政策。
- 可以与各国交易。
- 可以通过外交或战争成为国家成员。

### 11.2 国家政策影响阶级

国家政策不是直接修改城镇人口。

而是改变人口的经济环境和制度环境。

例如：

国家提高工业税。

结果可能是：

- 工人实际收入减少。
- 工厂利润下降。
- 商人投资意愿降低。
- 国家税收增加。
- 社会矛盾上升。

国家降低农业税。

结果可能是：

- 农民收入提高。
- 粮食供应稳定性增加。
- 国库收入下降。
- 农业阶级满意度上升。

这种间接影响应成为国家管理的核心。

---

## 12. 名人与官员系统

这是游戏最重要的随机乐趣系统之一。

建议单独建立 `Character System` 插件。

### 12.1 名人产生

每个城镇的八大阶级都有机会产生名人。

生成条件与所属阶级有关。

例如：

- 农民产生农业专家、地方领袖。
- 工人产生工匠大师、工业组织者。
- 商人产生商业巨头、贸易专家。
- 官僚产生行政专家、政治家。
- 祭司产生宗教领袖。
- 学者产生科学家、教育家。
- 军人产生军事统帅。
- 文艺家产生艺术家、文化领袖。

名人的出现具有随机性。

但其概率受城镇经济、人口、教育水平和相关建筑影响。

### 12.2 名人属性

每个人物拥有六种主要能力属性：

| 属性 | 影响 |
|---|---|
| 行政 | 管理、政策执行、组织能力 |
| 经济 | 生产、财政、商业 |
| 军事 | 战争、训练、指挥 |
| 学识 | 科技、教育、创新 |
| 外交 | 谈判、关系、外交活动 |
| 文化 | 宗教、艺术、社会影响 |

属性范围：0～100。

人物还有：

- 所属阶级。
- 出生城镇。
- 年龄。
- 忠诚度。
- 野心。
- 声望。
- 政治倾向。
- 性格。
- 特殊技能。
- 缺陷。
- 人际关系。
- 所属派系。

### 12.3 名人稀有度

采用人才评级：

| 等级 | 定位 |
|---|---|
| 普通 | 一般人才 |
| 优秀 | 具备明显专长 |
| 杰出 | 某个领域能力突出 |
| 传奇 | 具有改变局势的特殊能力 |

评级不应该简单地等于六种属性总和。

有些人物可能行政能力极强，但军事能力很差。

也有可能某位人物只有中等基础属性，却拥有极强的特殊技能。

例如：

**人物：阿尔文**

所属阶级：商人。

行政：55  
经济：96  
军事：20  
学识：68  
外交：88  
文化：45

特殊技能：
- 商业网络：国内市场运输效率提高。
- 价格洞察：能够发现其他国家的贸易机会。

负面特质：
- 个人利益优先。
- 不喜欢严格的国家贸易管制。

这类人物在开放贸易的国家可以非常强大，但在高度集权的国家未必表现出色。

### 12.4 名人随机抽取系统

建议设计为人才寻访。

国家通过以下方式获得人才寻访机会：

- 时间自然积累。
- 城镇人口发展。
- 建立学院。
- 提高国家声望。
- 外国人才招募。
- 特殊随机事件。

每次人才寻访出现三张候选人物卡。

玩家可以选择其中一名进行招募。

候选人的特点由随机种子和人才生成规则决定。

初步概率配置：

| 评级 | 基础出现概率 |
|---|---:|
| 普通 | 55% |
| 优秀 | 30% |
| 杰出 | 12% |
| 传奇 | 3% |

以上只是初始调试值，后续需要通过游戏数据调整。

可以增加保底机制，例如连续多次没有出现杰出及以上人才时，提高下一次出现概率。

**重要原则：所有名人必须有实用价值，低稀有度不代表废物。**

高级人物可以拥有更多特殊技能，但也可能具有更强烈的负面性格和政治野心。

### 12.5 名人任命

国家可以任命名人担任：

- 财政官。
- 行政总管。
- 军事统帅。
- 外交官。
- 科技主管。
- 宗教领袖。
- 文化主管。
- 城镇总督。

任命后，名人将影响对应系统。

例如：

经济官员经济属性越高，贸易和财政决策越有效。

军事统帅军事属性越高，军队组织与作战效果越好。

### 12.6 名人独立人格

这是必须有的设计。

名人不是普通装备。

他们拥有个人诉求。

例如：

- 希望获得更多权力。
- 希望提高所属阶级地位。
- 希望建立自己的政治派系。
- 希望发动战争。
- 希望扩大商业自由。
- 希望扩大宗教影响。
- 希望减少国家对地方的干预。

每个名人还有自己的人际关系。

关系值范围建议：-100～100。

包括：

- 友好。
- 信任。
- 师徒。
- 政治盟友。
- 商业伙伴。
- 家族关系。
- 竞争。
- 仇恨。

人物关系会影响国家政策执行。

例如：

玩家下令某位总督提高商业税。

但总督与当地商人领袖存在亲密关系。

此时总督可能：

- 完全执行。
- 部分执行。
- 拖延执行。
- 通过其他政策绕过命令。

### 12.7 命令执行率

建议不要将命令设计为简单的成功或失败。

采用执行程度：

`执行率 = 基础服从度 + 官员能力 + 地方支持度 + 人际关系加成 - 政策阻力 - 腐败影响`

最终结果限定在 0～100%。

玩家可以查看命令执行预估。

同时，执行过程允许出现少量随机波动。

### 12.8 名人生命周期

名人拥有年龄和生命周期。

人物可能：

- 晋升。
- 退休。
- 生病。
- 死亡。
- 被罢免。
- 叛逃。
- 发动政变。
- 建立政治派系。

死亡后可以产生：

- 历史声望。
- 纪念建筑。
- 著作或遗产。
- 后继人物。
- 历史事件。

这样人才系统可以成为整个游戏历史叙事的来源。

---

## 13. 国家财政系统

国家财政与城镇财政必须分离。

国家财政至少包含：

- 国库资金。
- 年度税收。
- 年度支出。
- 预算计划。
- 债务。
- 国家资产。
- 战争储备。

可以设计几个简单的财政政策：

1. 稳健财政。
2. 发展财政。
3. 军事财政。
4. 商业财政。
5. 紧缩财政。

国家可以调整各项预算。

例如：

提高军事预算会改善装备、训练和士气，但减少其他系统可用资金。

允许国家出现赤字，但需要产生债务和信用风险。

如果长期赤字，可能发生：

- 官员欠薪。
- 军队欠饷。
- 公共建设停滞。
- 通货与市场问题。
- 城镇自治诉求增加。

---

# 第五部分：国家主要发展系统

## 14. 政治系统

政治系统负责解决阶级、官员和国家之间的权力分配。

### 14.1 政治制度

建议采用逐渐解锁的制度。

- 部落议事制。
- 贵族议会制。
- 君主制。
- 官僚制。
- 商业寡头制。
- 城邦共和制。
- 代表议会制。

这些制度不应只是不同数值加成。

它们应该影响：

- 官员任命方式。
- 税收权限。
- 阶级代表权。
- 城镇自治。
- 国家决策效率。
- 政策改变成本。
- 名人政治影响力。

### 14.2 政治派系

不同阶级和名人可以形成政治派系。

例如：

- 农民派系。
- 商人派系。
- 军事派系。
- 宗教派系。
- 官僚派系。
- 改革派系。

派系拥有支持者、影响力和诉求。

玩家制定政策时，需要考虑派系之间的关系。

### 14.3 政治事件

例如：

- 商人要求贸易自由。
- 农民要求减税。
- 军人要求增加军费。
- 学者要求教育改革。
- 祭司要求提高宗教权力。
- 官员要求扩大行政预算。

政治系统的本质不是每天产生政治事件，而是在关键政策和重大利益冲突时产生决策。

---

## 15. 宗教系统

宗教系统由祭司阶级主导。

每种宗教拥有：

- 宗教名称。
- 基本教义。
- 社会影响力。
- 传播能力。
- 仪式。
- 宗教建筑。
- 主要支持阶级。

### 15.1 宗教传播

宗教传播受到：

- 祭司人口。
- 宗教建筑。
- 文化交流。
- 商业交流。
- 国家政策。
- 战争与移民。

影响。

### 15.2 宗教与国家关系

国家可以选择：

- 支持一种宗教。
- 宗教宽容。
- 多宗教共存。
- 限制宗教。
- 政教合一。
- 推行世俗化。

不同政策对祭司阶级、社会稳定、政治合法性和外交关系产生不同影响。

### 15.3 宗教冲突

当城镇存在不同宗教群体时，可能发生：

- 文化融合。
- 宗教竞争。
- 信仰冲突。
- 宗教改革。
- 宗教起义。

不要设计成每座城镇都必须处理复杂的宗教人口模拟。

初期只需要宗教影响力和信仰满意度两个核心变量。

---

## 16. 科技系统

科技系统主要由学者阶级推动。

科技采用分支树。

初步分成六个发展方向：

| 科技分支 | 主要内容 |
|---|---|
| 农业 | 灌溉、轮作、畜牧 |
| 工业 | 采矿、冶炼、机械 |
| 商业 | 市场、货币、贸易 |
| 行政 | 文字、法律、官僚制度 |
| 军事 | 战术、武器、攻城、海军 |
| 文化 | 教育、建筑、艺术 |

科研流程：

1. 学者生产知识。
2. 国家或城镇积累科研资源。
3. 玩家选择研究项目。
4. 研究进度逐步增加。
5. 技术解锁新建筑、政策或单位。

### 16.1 科技随机事件

在研究过程中允许出现随机技术突破。

例如：

- 农业工具改良。
- 冶炼技术发现。
- 新型航海技术。
- 医疗知识突破。
- 行政管理创新。

这些事件应该是有限的随机加成，而不是让正常科研变成完全不可预测。

### 16.2 技术传播

科技不是所有城镇同步解锁。

国家拥有基础技术体系，但某些技术需要通过以下方式传播：

- 学者交流。
- 人才流动。
- 商业接触。
- 战争俘获。
- 外交合作。

城镇可以拥有局部技术优势。

---

## 17. 军事系统

军事系统主要依赖军人阶级。

### 17.1 军队组成

第一版建议采用六种基本兵种：

| 兵种 | 特点 |
|---|---|
| 民兵 | 成本低、防御一般 |
| 步兵 | 基础主力 |
| 弓兵 | 远程攻击 |
| 骑兵 | 高移动、高机动 |
| 攻城部队 | 攻城能力 |
| 海军 | 海上运输与作战 |

后期可以扩展枪兵、重装骑兵、火器部队等。

### 17.2 军队属性

每支军队包含：

- 人数。
- 攻击。
- 防御。
- 生命。
- 士气。
- 训练度。
- 装备。
- 补给。
- 移动力。
- 指挥官。

### 17.3 地形对战争的影响

| 地形 | 效果 |
|---|---|
| 平原 | 适合常规作战与骑兵 |
| 森林 | 防御加成 |
| 丘陵 | 防御与视野优势 |
| 山地 | 高防御、低移动 |
| 沼泽 | 行军困难 |
| 河流边界 | 渡河受到惩罚 |
| 海岸 | 海陆联动 |
| 山口 | 适合建立堡垒 |

### 17.4 战斗判定

建议初期使用简化战斗计算，而不是一开始就制作复杂战术棋盘。

`战斗力 = 基础攻击力 × 兵力 × 训练度 × 士气 × 补给系数`

再结合：

- 地形。
- 指挥官能力。
- 双方兵种克制。
- 防御设施。
- 随机战斗波动。

决定最终结果。

随机波动只占战斗结果的一部分。

优秀指挥官能够提高胜率，但不能保证永远获胜。

### 17.5 补给系统

军队远离本国城镇时需要补给。

补给来源：

- 本国城镇。
- 盟友城镇。
- 建立的补给线。
- 后勤建筑。
- 军事运输。

补给不足会导致：

- 士气下降。
- 移动能力下降。
- 战斗能力降低。
- 人员损失。

这一机制可以让山谷、河流、山口和交通要道具有真正的军事意义。

## 18. 艺术与文化系统

由文艺家阶级主导。

主要产出：

- 文化值。
- 城镇声望。
- 国家声望。
- 艺术品。
- 历史作品。
- 文化影响力。

文化建筑：

- 剧院。
- 图书馆。
- 博物馆。
- 艺术学院。
- 纪念碑。
- 节庆广场。

### 18.1 艺术品系统

随机产生艺术家和艺术作品。

每件作品具有：

- 创作者。
- 作品类型。
- 创作时间。
- 艺术价值。
- 文化影响力。
- 历史意义。

艺术品可以成为收藏、交易、外交和文明遗产的一部分。

### 18.2 文化竞争

文化影响力能够影响其他国家城镇的文化倾向。

文化优势可以带来：

- 外交声望。
- 人才吸引力。
- 旅游收入。
- 城镇人口增长。
- 文化传播。

---

## 19. 外交系统

外交以国家关系为单位。

每两个国家之间拥有：

- 友好度。
- 信任度。
- 贸易关系。
- 军事威胁。
- 历史恩怨。
- 意识形态差异。
- 利益冲突。

外交行为：

- 建立邦交。
- 商业协议。
- 贸易开放。
- 互不侵犯。
- 防御同盟。
- 军事同盟。
- 科技交流。
- 城镇通行权。
- 要求赔款。
- 领土谈判。
- 结盟。
- 宣战。
- 停战。
- 附属关系。

外交人员的能力、人物关系和国家信誉会影响谈判结果。

独立城镇也应拥有外交系统。

国家可以通过贸易优惠、保护承诺和政治谈判争取独立城镇。

# 第六部分：随机性与 AI 系统

## 20. 随机事件系统

所有随机内容使用统一的随机事件框架。

事件分为：

1. 地图事件。
2. 城镇事件。
3. 人口事件。
4. 经济事件。
5. 政治事件。
6. 名人事件。
7. 科技事件。
8. 宗教事件。
9. 军事事件。
10. 外交事件。

事件由条件触发，而不是完全随机弹出。

例如：

连续两年粮食减产，可能触发饥荒事件。

某名人声望过高且拥有军队支持，可能触发政治事件。

某个城镇长期贸易繁荣，可能产生国际商人入驻事件。

### 20.1 随机公平性

所有随机系统必须满足：

- 使用可复现的随机种子。
- 不因界面操作顺序改变核心随机结果。
- 不允许读取玩家隐藏信息获得不公平 AI 优势。
- 随机概率能够在界面查看。
- 重要事件保留触发原因。
- 存档必须保存随机状态。

建议为地图、人物、经济事件、战斗分别使用不同随机数流。

这样某次战斗随机结果不会因为玩家查看了一张人物卡而发生变化。

## 21. AI 国家系统

AI 国家与玩家使用同一套规则。

不能给 AI 额外资源或者直接修改模拟结果。

AI 决策分为五层：

1. 国家战略。
2. 城镇发展。
3. 财政管理。
4. 外交军事。
5. 名人任命。

### 21.1 AI 战略性格

AI 国家拥有不同性格：

- 扩张型。
- 商业型。
- 文化型。
- 科技型。
- 防御型。
- 宗教型。
- 平衡型。

性格决定其行为权重，而不是简单的固定脚本。

### 21.2 AI 城镇管理

AI 每年检查：

- 食物是否充足。
- 市场是否短缺。
- 财政是否出现赤字。
- 人口是否失业。
- 阶级矛盾是否严重。
- 是否需要建设新的设施。
- 是否有值得任命的人才。

AI 不应该每年执行完全相同的行为。

### 21.3 名人 AI

每位名人拥有自己的行动倾向。

当玩家不直接管理时，人物会依据：

- 职位。
- 性格。
- 个人目标。
- 国家政策。
- 所属派系。
- 人际关系。

提出建议或自行执行允许范围内的决策。

玩家可以设置：

- 完全自主。
- 提出建议后等待批准。
- 在授权预算内自主执行。
- 仅允许执行指定任务。

这样玩家可以选择亲自管理，也可以让优秀名臣承担大量管理工作。

# 第七部分：胜利与游戏体验

## 22. 游戏胜利条件

不推荐将游戏设计成只有军事征服一种胜利方式。

建议有四种主要成就路线。

| 路线 | 核心要求 |
|---|---|
| 军事霸权 | 控制关键领土、建立军事优势 |
| 经济繁荣 | 建立庞大国内外贸易体系 |
| 科技文明 | 实现多项技术突破 |
| 文化影响 | 形成跨国家的文化优势 |

外交与政治方面可以产生特殊胜利事件，例如多个国家接受某种国际秩序。

### 22.1 游戏结束方式

建议支持：

- 预设回合数胜利。
- 文明成就胜利。
- 军事征服胜利。
- 无尽沙盒模式。

游戏结束后显示完整历史统计。

玩家可以查看：

- 国家历史。
- 城镇发展。
- 历代名人。
- 重要战争。
- 历史政策。
- 科技突破。
- 经济变化。
- 文明排名变化。

这些数据可以成为玩家反复游玩的动力。

主界面采用六边形世界地图作为中心。

推荐布局：

**顶部：国家状态栏**

展示：

- 国库。
- 人口。
- 粮食。
- 科研。
- 信仰。
- 稳定度。

**左侧：地图导航**

展示：

- 地块信息。
- 城镇列表。
- 国家领土。
- 地图图层。

**右侧：管理面板**

根据当前选中对象显示：

- 城镇详情。
- 阶级详情。
- 名人详情。
- 国家政策。
- 军队详情。

**底部：时间控制**

- 当前年份。

- 地形图层。
- 资源图层。
- 人口密度图层。
- 阶级分布图层。
- 贸易网络图层。

- 宗教分布图层。

- 国家控制图层。

### 23.2 解释性 UI

这是项目必须优先实现的功能。

凡是数值发生明显变化，都要能查看原因。

例如：

点击城镇粮食短缺提示，显示：

粮食需求：1,200  
粮食产量：800  
进口：100  
实际可用：900  
粮食缺口：300

玩家不需要猜测系统发生了什么。

# 第九部分：联机系统

## 24. 单人与本地游戏

所有模式共用一套模拟核心。

单人：
- 玩家国家由玩家控制。
- 其余国家由 AI 控制。

本地热座：
- 多个玩家依次管理各自国家。
- 提交回合后统一结算。
- 可以隐藏其他玩家的私人信息。

未来也可扩展局域网模式。

## 25. 在线多人

建议初期采用房主权威模式。

玩家通过房间进入同一场游戏。

建议支持：

- 2～8 人。
- Steam 邀请。
- 房间创建。
- 房间搜索。
- 准备状态。
- 回合提交。
- 断线重连。
- 玩家退出。
- AI 接管离线玩家。

### 25.1 在线回合流程

1. 房主创建游戏。
2. 玩家加入房间。
3. 各玩家提交自己的回合操作。
4. 服务器端权威的模拟核心进行结算。
5. 广播结果和必要的状态快照。
6. 所有玩家进入下一回合。

### 25.2 同步方式

不建议同步每个画面对象。

只同步：

- 玩家命令。
- 必须公开的游戏状态。
- 回合编号。
- 状态校验数据。
- 存档快照。

这样能够降低网络负担。

所有改变世界状态的操作都必须经过统一命令系统。

### 25.3 网络安全

客户端不能直接指定自己的金钱、人口和战斗结果。

房主负责校验玩家命令是否合法。

重要操作需要检查：

- 操作者身份。
- 当前回合。
- 资源是否足够。
- 操作目标是否合法。
- 是否满足游戏规则。

初版不做复杂的竞争性反作弊系统，但架构不能信任任意客户端数据。

# 第十部分：技术架构和插件系统

## 26. 游戏引擎选择

采用 Godot 4.7.2 Stable。

主要理由：

- 2D 开发能力成熟。
- 支持六边形网格的自定义实现。
- GDScript 适合 AI 辅助开发。
- MIT 许可证，适合商业项目。
- 支持桌面平台导出。
- 有现成的多人游戏网络接口。
- 可以使用 GDExtension 扩展原生功能。

本项目不采用实验性引擎版本。

引擎升级必须经过独立测试。

## 27. 核心系统定义

最重要的架构要求：

**Core 必须可以在完全没有游戏规则插件的情况下独立运行。**

Core 不知道农民是什么，不知道城镇如何产生收入，也不知道军队如何战斗。

它只负责提供底层能力。

### 27.1 Core 必须包含

1. 游戏启动入口。
2. 游戏主窗口。
3. 场景管理。
4. 插件加载器。
5. 数据注册中心。
6. 统一事件总线。
7. 统一命令总线。
8. 确定性随机数系统。
9. 回合调度器。
10. 存档管理。
11. 配置管理。
12. 本地化接口。
13. 调试日志。
14. 基础 UI 容器。
15. 插件依赖检查。

### 27.2 Core 不应包含

以下功能不能直接写进 Core：

- 地图生成规则。
- 城镇人口增长。
- 八大阶级。
- 经济生产。
- 贸易逻辑。
- 政治制度。
- 科技树。
- 军队战斗。
- 名人生成。
- 宗教传播。
- 外交行为。
- AI 决策。

这些都通过插件实现。

### 27.3 Core 独立运行标准

即使所有游戏玩法插件被禁用：

- 程序仍然能够启动。
- 能够显示主界面。
- 能够读取配置。
- 能够加载和卸载插件。
- 能够展示插件状态。
- 能够保存和加载基础运行数据。
- 能够运行一个简单的 Core Demo。

Core 不应因缺少地图插件而崩溃。

## 28. 官方插件结构

建议建立以下插件。

| 插件 | 主要职责 |
|---|---|
| world_map | 世界地图、地块、随机生成 |
| town_system | 城镇基础数据 |
| population | 人口和八大阶级 |
| economy | 经济与市场 |
| governance | 行政和政治 |
| religion | 宗教 |
| technology | 科技 |
| military | 军事 |
| culture | 艺术与文化 |
| characters | 名人与官员 |
| diplomacy | 外交 |
| event_system | 随机事件 |
| ai_nations | AI 国家 |
| multiplayer | 联机适配 |
| game_ui | 完整游戏界面 |

插件之间通过统一 API 通信。

例如：

经济插件不能直接修改人口插件的内部变量。

它只能发布：

`Economy.WagesChanged`

人口插件收到事件后更新相关状态。

这样能够降低模块耦合。

## 29. 插件标准接口

每个插件必须提供：

- 插件 ID。
- 插件版本。
- 依赖插件。
- 数据注册。
- 系统注册。
- 回合处理接口。
- 事件订阅。
- 命令注册。
- 存档接口。
- 关闭接口。

建议统一采用插件清单文件。

例如：

```json
{
  "id": "population",
  "name": "Population System",
  "version": "1.0.0",
  "api_version": "1.0",
  "dependencies": [
    "town_system"
  ],
  "load_priority": 30
}
```

插件加载时检查：

1. 插件文件是否存在。
2. 插件版本是否兼容。
3. 依赖是否齐全。
4. 是否有循环依赖。
5. 数据 ID 是否重复。
6. 系统是否注册成功。

任何关键检查失败，都应停止加载相关插件并写入错误日志。

# 第十一部分：数据与开发规范

## 30. 数据驱动原则

所有可调整的游戏数据均应尽量使用配置文件。

建议采用：

- JSON：基础数据与插件清单。
- Godot Resource：游戏对象配置和资源引用。
- CSV：方便批量编辑的平衡表。
- GDScript：系统运行逻辑。

例如，阶级消费数据不能直接写在多处代码里。

应当统一配置。

```json
{
  "id": "worker",
  "name": "工人",
  "unlocks": [
    "workshop"
  ],
  "consumption": {
    "food": 1.0,
    "tools": 0.2,
    "textiles": 0.1
  },
  "outputs": [
    "processed_goods"
  ]
}
```

数值仅作为配置结构示例。

## 31. 存档系统

所有存档都必须包含：

- 存档版本。
- 游戏版本。
- 引擎版本。
- 地图随机种子。
- 世界生成版本。
- 当前回合。
- 全球状态。
- 国家状态。
- 城镇状态。
- 人物状态。
- 随机数状态。
- 启用插件列表及版本。

存档采用版本化结构。

插件必须能自行保存和读取自己的状态。

未来更新游戏时要支持存档迁移。

### 31.1 存档原则

- 定期自动存档。
- 重要行动前保留恢复点。
- 回合结算后保存快照。
- 存档失败不得覆盖最后一个有效存档。
- 不兼容插件必须明确报告。

## 32. 确定性模拟规范

这是联机系统能够正常工作的前提。

以下操作必须经过统一模拟接口：

- 人口变化。
- 商品生产。
- 商品交易。
- 税收。
- 战争。
- 人物生成。
- 随机事件。
- AI 决策结果。

模拟系统必须有统一处理顺序。

建议每年结算顺序：

1. 执行已批准的政策和命令。
2. 处理建筑与设施。
3. 执行农业和工业生产。
4. 执行贸易和市场价格调整。
5. 发放收入、支付工资。
6. 进行阶级消费。
7. 计算财政与税收。
8. 计算人口增长与阶级流动。
9. 计算社会满意度与矛盾。
10. 推进科技、宗教、艺术。
11. 执行军事行动。
12. 执行外交和 AI 决策。
13. 生成年度事件。
14. 生成年度报告。
15. 保存回合快照。

各插件通过注册处理阶段参与模拟，不能自行在不确定的时间修改其他系统状态。

# 第十五部分：项目风险与处理方案

## 38. 需要重点防范的风险

### 风险一：系统过多导致开发失控

处理方法：

插件化、阶段验收、统一接口。

任何新增功能都要先说明依赖关系和数据流向。

### 风险二：经济模拟过于复杂

处理方法：

不模拟每一个居民的具体行为。

按照阶级人口组和城镇市场聚合计算。

只在重要人物和重大历史事件上使用个体级模拟。

### 风险三：随机性变成不可理解的黑箱

处理方法：

所有随机事件记录触发条件、概率和结果。

重要结果允许玩家回溯原因。

### 风险四：AI 产生不合理决策

处理方法：

AI 必须使用玩家可以使用的命令接口。

AI 决策必须考虑资源预算和行动合法性。

先使用规则权重 AI，后期再考虑更复杂的策略模型。

### 风险五：联机系统导致架构返工

处理方法：

从 Core 阶段就建立命令系统、确定性随机数系统和回合结算流程。

不能先完成一套不可同步的单机逻辑，再试图强行添加联机。

### 风险六：名人系统过于强大

处理方法：

名人提供能力加成，但不直接代替经济系统。

所有特殊技能都应该有作用范围和限制。

同时设置忠诚、性格和权力平衡机制。

### 风险七：AI 交接后代码质量下降

处理方法：

每个插件必须独立文档、接口说明、测试和 Git 历史。

禁止 AI 在不了解现有结构时重新设计已经完成的 Core。

# 第十六部分：项目最终目标

## 39. 最终产品应具有的特色

我建议最终将游戏的主要特色集中在五个方面。

**一、世界具有差异。**

每次生成的地图，都能形成不同的国家发展路线。

**二、城镇具有生命力。**

城镇不是一堆固定产出建筑，而是由不同阶级共同组成的经济社会。

**三、社会具有矛盾。**

玩家不能同时满足所有阶级，政策选择必然带来利益交换。

**四、人才具有随机惊喜。**

玩家有机会得到影响文明历史的传奇人物，也可能得到有能力却难以管理的人物。

**五、文明具有历史感。**

每场游戏都应当形成一段独特的历史，具有自己的名人、战争、城镇、政治变化和发展轨迹。

最终，玩家回顾游戏时，看到的应该不是简单的国家数值，而是：

- 哪座城镇从小村庄发展成帝国首都。
- 哪位名臣改变了国家经济。
- 哪位军事统帅建立了辉煌战绩。
- 哪场战争改变了国际格局。
- 哪次阶级冲突导致政治制度改革。
- 哪个独立城邦最终加入了国家。
- 哪项技术推动了文明发展。

**这才是《群邦纪元》希望提供的长期游戏体验。**

# 附录 B：首批开发任务

第一个负责开发的 AI 不应该直接编写整个游戏。

应该按以下顺序执行：

**任务 1：建立项目仓库**

创建 Godot 项目、Git 仓库和项目文档。

**任务 2：建立 Core**

先确保 Core 可以独立运行。

**任务 3：建立插件系统**

创建一个测试插件，验证插件注册、加载、事件通信和卸载流程。

**任务 4：建立模拟调度器**

创建年度回合处理框架，验证多个插件能够按顺序处理游戏状态。

**任务 5：建立存档框架**

验证 Core 和插件数据都能够保存与加载。

**任务 6：建立世界地图插件**

先绘制六边形地图，再实现随机生成。

完成任务 1～6 后，才进入城镇开发。

**首要目标不是尽快看到一张漂亮的游戏地图，而是建立一个后续 AI 能够持续扩展、不会频繁推倒重来的技术底座。**
