# 历史方案归档

本目录存放《群邦纪元》立项阶段由四个 AI 依据根目录 `Readme.md` 独立产出的设计方案。**它们是过程材料，不是现行规则**；现行设计以 [`../GDD.md`](../GDD.md) 为唯一来源。

| 方案 | 原始文件 | 篇幅 | 定位与特点 | 主要短板（未进终稿的部分） |
|---|---|---:|---|---|
| DeepSeek | [GDD.md](./deepseek-version/GDD.md) | ~16 KB | 均衡、克制，最早给出「五类抽卡 + 三循环 + Core 最小循环」的完整闭环 | 缺少可执行的工程契约（无 hook、无确定性方案、无无头测试） |
| Gemini | [GDD.md](./gemini-version/GDD.md) | ~19 KB | 戏剧性最强：三重抽卡、抗命/结党/养肥再杀、倾销与断水 | 粒度用「月」，回合数与联机成本失控；数值与公式偏叙事 |
| GPT | [GDD.md](./gpt-version/GDD.md) | ~67 KB | 覆盖最全：16 地形、12 商品、完整 UI/联机/路线图/风险 | 内容量大但抽象不足，商品与地形过细；缺工程化的确定性/测试方案 |
| Qoder | [GDD.md](./qoder-version/GDD.md)<br>[ARCH.md](./qoder-version/ARCH.md)<br>[ROADMAP.md](./qoder-version/ROADMAP.md) | ~36 KB | 工程最硬：五层地块、单求解器、AP 瓶颈、政策向量、可无头验收的路线图、C# SimCore | 规则数值偏抽象，戏剧性与「抽卡爽感」着墨较少 |

## 终稿如何取舍

- 骨架与工程契约（Core/插件、hook、确定性 RNG、存档/迁移、无头标定、M0–M11）来自 **Qoder**。
- 抽卡体系与名人戏剧性（稀有度、保底、抗命、抄家、倾销、断水）来自 **Gemini**，并吸收 DeepSeek 的五类卡池。
- 年度回合 + 四季结算、人口单位、Core 与插件清单、提交节点来自 **GPT**。
- 产品定位、10 条核心循环、经济三循环的简洁表述来自 **DeepSeek**。
- 相互冲突处以「可解释、可测试、可联机」三条标准裁决，逐项对照见 [`../GDD.md` 附录 C](../GDD.md)。

## 使用约定

1. 不要把本目录的旧数值直接抄进代码；它们与终稿的数值表不一致。
2. 若某条旧设计值得复活，先写进 `docs/CHANGELOG-DESIGN.md` 并说明理由，再改 `GDD.md`。
3. 本目录只读；归档不再更新。
