# BALANCE · 数值标定现状与标定方法

> 规范来源：GDD §4.2（公式一/三）、§5.7（数值基线）、附录 A §8（人口）、附录 D（单位）、
> §12（M5 起每里程碑跑多策略基线，某策略胜率 > 55% 判未标定）。
> 实现：`src/Plugins/core.basic/SeasonRules.cs` + `src/Plugins/core.basic/TownOps.cs` + `data/core.basic/*.json`。
>
> **这份文档写的是「现在这套数跑出来是什么样」，不是「应该怎么调」。**
> 玩法判断归设计者；这里只保证每一次改数都留下可比的轨迹，并且把公式的解析解算出来，
> 免得把「公式跑出来的必然结果」误当成「参数没调好」。

## 0. 一分钟版

- **数值不住在代码里**。λ、需求、期望、上限、造价、损耗全在 `data/core.basic/*.json`（37 条记录）；
  代码里只剩「式子的形状」和 §4.2 明写的闸门常数（1.45、0.35、60、55/30、0.04）与 §3.6 的水利系数 1.15。
- **改一个数的动作**：改 JSON → `sim check` → `sim run --seed 42 --turns 200 --headless --out analysis/out/demo.csv`
  → 和上一份轨迹比。命令全在 §6。
- **M1 的循环有解析解**（§3）：地紧约束时平衡人口 `P* = 2 × Cap × Facility ÷ need`，
  且**平衡点必然落在 S\* = 29（反抗线以下）**。所以「放任不管 → 全国造反」不是 bug，是这三条公式的交点。
  要让它不造反，得加缓解阀（M3 价格、M4 税负、M5 贸易），不是把 0.04 调小。
- **现在没标定的东西比标定完的多**：价格、税、AP、阶级、军事、信仰全没接（§7）。
  M1 只标了「粮—人—满意度」这一条闭环的量纲。

## 1. 三条公式的常数从哪来

### 公式一 · 转化（`SeasonRules.Produce`，第 3 步首）

`Out = min( P × λ × Tech × η(S) , Cap × Facility )`，`η(S) = 0.6 + 0.4 × S/100`

| 符号 | 现在值 | 住在哪 | 备注 |
|---|---:|---|---|
| λ（农民人均产粮） | 2.40 石/人/年 | `class.peasant` → `output.food` | §4.3 照抄 |
| 口粮需求 | 1.00 石/人/年 | `class.peasant` → `consumes.food` | λ/need = 2.40 ⇒ 一个人最多余养 1.4 个非农业人口 |
| Tech | 1.00 | 硬编码（`SeasonRules.cs:32`） | M6 换科技卡倍率 1.0–2.5，届时进数据 |
| η(S) | 0.60–1.00 | 0.6 / 0.4 是 §4.2 的闸门常数 | 满意度 50 → η = 0.80，正是 §4.9 算例的那一步 |
| Cap | Σ 辖地 `hex.yieldFood` | `landform.*` → `potential.food`；`water.*` 覆盖水体格 | 水体格不进辖地。M2 切片四后 Y = (地表潜力 + 形胜地力) × 形胜倍率 × 资源倍率 × 水利系数（§3.6） |
| Facility | 1.00–1.45 | `building.farm` → `facility` = 0.15/级 × maxLevel 3 | §4.2 封顶 1.45 由 `TownOps.cs:216` 与不变量 `basic.ranges` 双重把关 |

### 公式三 · 满意度（`SeasonRules.Satisfaction`，第 12 步首）

`S* = 基线 + 60(s−e) − 20·税负 + 10·政策 + 10·信仰 − 15·矛盾 + 8·地位`
`S ← clamp(S + 0.35(S*−S) + ξ, 0, 100)`，`ξ ~ N(0, 2)`

| 参数 | 值 | 住在哪 |
|---|---:|---|
| 基线 | 50 | `class.peasant` → `satisfaction.baseline` |
| e（期望） | 0.85 | `class.peasant` → `satisfaction.expects` |
| 60（s−e 权重） | 60 | `SeasonRules.cs:133`，§4.2 常数 |
| 0.35（收敛速度） | 0.35 | `SeasonRules.cs:138`（`Fix.FromPercent(35)`） |
| ξ 噪声 | N(0, 2) | `SeasonRules.cs:137`，流命名 `satisfaction.<阶级>.T<回合>` |
| 状态分档 | >55 服从 / 30–55 抱怨 / <30 反抗 | `SeasonRules.cs:144`，§4.2 原文 |
| 升级闸门 | 连续 2 年 S<30 才升一级（第 2 年怠工、第 4 年罢工、第 6 年暴动） | **已兑现**：`town.riot.<阶级>` 分阶级计数，`SeasonRules.cs` 的 `statusMult`（0.85 / 0.60）；抗税 −50% 等税制（M5） |
| 暴动倒计时 | 3 年 → 城镇脱离原属国 | **已兑现**：`town.countdown`；镇压要军力（M7），M4 只有「让步」把暴动降回罢工 |

s = 1.00（满口粮）⇒ S\* = 59；s = 0.85（正好满足期望）⇒ S\* = 50；s = 0.50 ⇒ S\* = 29。
**这三档是 M1 全部的政治张力来源**，因为它把「粮食够不够」直接翻译成了「造不造反」。

### 公式二 · 粮价（`Pricing.Price`，第 6 步 Summer，OnPriceForm hook）

`p_{t+1} = clamp( p_t × (1 + α × (D − S) / max(S, 0.5) + shock) , 0.2 × p0 × κ , 5 × p0 × κ )`
M3 阶段 κ 固定为 1.0（M_global = M_ref），所以 clamp 简化为 `[0.2×p0, 5×p0] = [0.80, 20.00]`。

| 参数 | 值 | 住在哪 | 备注 |
|---|---:|---|---|
| p0（基准价） | 4.00 银/石 | `good.food` → `basePrice` | GDD §5.1 原值，不改 |
| α（城镇内循环系数） | 0.30 | `Pricing.cs` 硬编码 | GDD 附录 A §2 原值 |
| shock 标准差 | 0.04 = 4% | `Pricing.cs` 硬编码 | `Rng.NextGaussian(0, 0.04)`，流名 `price.good.food.T{回合}` |
| 下限 | 0.2 × p0 = 0.80 | `Pricing.cs` | GDD §5.3 clamp 闸门 |
| 上限 | 5 × p0 = 20.00 | `Pricing.cs` | GDD §5.3 clamp 闸门 |
| κ（金本位调整） | 1.00（固定） | GDD 公式里，M3 未接 | M_global/M_ref 的指数，M3 不跑全图所以固定 1 |

**时序注意**：公式二跑在第 6 步，消费跑在第 10 步。D（需求）是**预计值**
`need × pop`（不是第 10 步实际消费量），S（可售）是**当前库存**（第 3 步产出已加进 stock）。
这符合 GDD §5.4 的「市场先出清、后消费」语义。

**M3 不影响行为**：价格求解器只改 `town.price.*` 和快照，不修改库存。
人口/产出/满意度/不安的轨迹和 M1 完全相同（seed 42 / 200 年末态：2 城 / 163 / 82.75 / 26.58 / 2 不安）。
哈希变了是因为世界状态里多了 price/demand/supply 等字段。

**后续扩展**（M4 八阶级）：循环扩展到料/器/奢，κ 随 M_global 变化。

### 人口（`SeasonRules.Demography`，第 13 步首）

`ΔP = P × (0.04·粮安 − 0.03·拥挤 − 0.02·疫病 + 0.01·医疗)`，`粮安 = clamp(2s−1, −1, 1)`

- 只有 0.04 生效，其余三项 0（M3/M7 接）。⇒ **最大增长率 4%/年，翻倍 ≈ 18 年**（70/4）。
- 粮安在 s = 0.5 处过零：糊口不算余粮，s < 0.5 才真的减员。
- 零头进 `town.growth.<阶级>` 桶，向零截断后落人口（`SeasonRules.cs:201-211`）。

## 2. 定点刻度对定标的约束：小于 0.01 的量不许先物化

×100 定点（`Fix.Scale = 100`）意味着**任何中间量都只有 1/100 的分辨率**。
`0.04 × 粮安` 在 s ≤ 0.62 时是 0.00xx —— 先算它、再乘 P，就会被截成 0.00，
乘回去还是 0。于是人口在低粮安年份**永久冻结**，而不是慢慢涨。

这不是理论风险，是 seed 42 基线真实踩到的坑（2026-11-13 修，`8039610`）：
第 83 年起人口卡在 72 个百人单位，之后 117 年一动不动，因为那时 s ≈ 0.62。

**写法纪律**（`SeasonRules.cs:174-177` 的文档注释里也有这条）：

```csharp
// ✗ 中间量 0.008 先被截成 0.00
Fix rate  = Fix.Mul(Fix.FromPercent(4), secure);
Fix delta = Fix.Mul(Fix.FromInt(pop), rate);

// ✓ 先把 P 乘进去，全程只在最后截断一次：ΔP = P × 粮安 × 4 ÷ 100
Fix delta = Fix.Div(Fix.Mul(Fix.Mul(Fix.FromInt(pop), 4), secure), 100);
```

回归用例：`tests/SimCore.Tests/CoreBasicTests.cs` 的 `缺粮但不至于饿死时零头桶照样在涨`。
它把辖地压成「只够六成口粮」，然后断言第 13 步**往零头桶里写了正数**——
判据用桶而不是年末人口，因为不进位的年份人口本来就不该动。

同类要盯的点：`η(S)`、`0.35(S*−S)`、`60(s−e)` 都在 0.x–几十的量级，安全；
M3 接价格（4.00 石 × 小系数）、M4 接税率（20% × 小基数）时同样会撞这个坑。

## 3. M1 循环的解析解（先看这个再调参数）

设辖地粮潜力合计 `Cap`、设施 `F`、口粮需求 `need`，且**地为紧约束**（`Cap × F < P × λ × η`）。

1. 年产量 `Out = Cap × F`（与人口无关）。
2. 仓空时 `s = Out ÷ (need × P)`。
3. 零头桶不再进位 ⇔ 粮安 = 0 ⇔ `s = 0.5`。

⇒ **平衡人口 `P* = 2 × Cap × F ÷ need`**，且平衡点的满意度 `S* = 50 + 60(0.5 − 0.85) = 29`。

基线数据对得上：`Cap × F = 31.90 + 13.00 = 44.90` 石 ⇒ `P* = 89.8`。
这条解析式是 M1 单城单阶级的结论；M3/M4 接上多商品与状态机后，200 年轨迹会在 S≈29
压到怠工线并进入死亡螺旋（见 §4 的 123/200 年两行），所以 `P*` 只能当**上界直觉**用，
不能再拿「实测第 200 年人口 89」当验收。

这条解析式给出三个玩法判断，调参之前先确认要不要的是它们：

- **人口永远收敛到「刚够糊口的一半」**，也就是永远停在反抗线以下。
  M1 的地图上没有缓解阀（没有商人/工人阶级分摊需求、没有贸易补粮、没有科技抬 λ），
  所以「放任 = 全国造反」是公式的必然，不是标定失误。§5.8 剧本第 3 条提前在 M1 就出现了。
- **想抬高承载人口，只有三条路**：加地（铺城，受 §3.8 的「距最近城镇 ≥ 3 格」限制）、加田（Facility 封顶 1.45）、
  抬 λ（M6 科技）。农田的性价比可以手算：一块 3.00 平原 + 15% 设施 ≈ 4.5 石 ≈ **多养 9 人**。
- **`2 ×` 这个系数完全由「粮安过零点 = 0.5」决定**。把它改成 0.7（更贵的余粮门槛），
  平衡人口立刻降到 `Out/(0.7·need) ≈ 1.43 × Out`，满意度反而升到 S\* = 50 + 60(0.7−0.85) = 41（抱怨但不服从）。
  这是「饥荒频率 vs 人口天花板」的总开关，M3 标定市场之前先别碰它。

## 6. 改数之后跑什么

```bash
dotnet build                                             # 0 warning 0 error（TreatWarningsAsErrors）
dotnet test                                              # 106 条
dotnet run --project src/HexaCiv.Cli -- check            # 数据包 + 清单：dataHash 变了要认账
dotnet run --project src/HexaCiv.Cli -- run --seed 42 --turns 200 --headless --out analysis/out/demo.csv
dotnet run --project src/HexaCiv.Cli -- hash --seed 99 --turns 50   # 确定性自检（改了不该改的东西会红）
```

- 只改 JSON ⇒ 轨迹变、`dataHash` 变、测试仍应全绿（没有测试钉死基线数字，只有钉死公式的）。
- 改公式 ⇒ 先想清楚 `产出等于公式一的两个上限取小` / `满意度向S星收敛且只吃口粮一项`
  这两条会不会红：它们在测试里把 GDD 的公式**重算了一遍**，实现和文档各写一次，撞不上就说明有一边错了。
- 多个种子都要看：`for s in 7 42 99 1234; do … --seed $s --turns 200 …; done`。
  单一种子的满意度会被 ξ 的抽样骗。
- 价格是 M3 新增的 hook，`Pricing.Price` 里 `α=0.30`、shock 标准差 4% 是 GDD 常量，**不许为手感调**。
  要调先记进 `CHANGELOG-DESIGN.md` 模拟差异表。

`analysis/out/` 在 `.gitignore` 里（基线属于可再生成的产物），要留证据就把关键几行抄进本文件。

## 7. 与 §5.8 默认剧本的对照

| §5.8 要求 | 现状 | 差什么 |
|---|---|---|
| 前 20 年：农业剩余 → 人口增长 | ✅ 出现（第 3 年就在攒粮，4%/年增长） | — |
| 20–60 年：工人激增 → 粮价上涨 30–80% → 农民短暂繁荣 | 🟡 工人阶级与解锁链已接（§4.4 + §4.7 转化），粮价在跑；但价格还不影响消费分配 | M5 多镇贸易让价格真的影响分配 |
| 60–100 年：囤粮 + 定价失效 → 暴涨 → 反抗 → 暴动或转向 | 🟡 反抗与暴动倒计时已兑现（§4.2）；「商人囤粮」与「政策转向」不存在 | M5 贸易 + M7 镇压/政策 |
| 一直不管 → 某城独立或被吞并 | 🟡 暴动倒计时归零会让城镇独立；吞并与外交仍无 | M9 |

**结论**：§5.8 的后三条要等 M4–M5 才谈得上「标定」。现在能说出口的只有
「§4.9 的『地够粮不够』循环在 M1 里真的会出现，并且收敛到 §3 那条解析式给的点」。
M3 加了价格求解器，但它还不影响消费分配——价格目前是"随供需变化的数字"，
真实影响行为要等到 M5（多镇国内循环）把价格接进口粮分配逻辑。
