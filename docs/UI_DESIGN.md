# HexaCiv UI 设计方案

> 用途：交给后续 UI / UX / Godot AI 作为统一视觉与交互基准。
> 规则依据：`GDD.md`。本文件提出视觉呈现，不定义新玩法、数值、命令合法性或模拟规则；遇到冲突以 GDD 为准。
> 范围：桌面端 2D 单机优先，结构兼容热座与在线联机；M2 地图阶段可逐步采用其中的地图骨架，完整设计覆盖 GDD 垂直切片及后续国家、经济、名人等面板。

---

## 1. 设计目标与原则

玩家扮演的是国家意志，通过政令治理一群有利益、有脾气的城镇与阶级。UI 的工作是让玩家快速看清局势、理解后果、作出取舍，然后能追溯模拟为什么这样发展。

1. **地图是主工作区**：空间态势常驻，面板和报告围绕地图展开，不让玩家迷失在多层菜单中。
2. **先给结论，再给原因**：年报和详情先展示发生了什么，再展开公式与输入项；解释来自模拟记录，不在 UI 重算规则。
3. **所有指令都可审阅**：下达前展示目标、成本、AP 影响和已知执行条件；结果展示受理/拒绝/折扣执行及原因。
4. **宏观、聚合、可比较**：人口按阶级等聚合量呈现。除 GDD 名人卡以外，不把普通居民做成可点选个体。
5. **信息分层而非堆满**：地图提供概览，选中对象提供上下文，详情抽屉提供证据；高阶数据默认收起。
6. **确定性呈现**：读数、顺序和日志来自同一模拟快照；动画只表达已发生状态，不改变命令顺序或模拟结果。
7. **桌面优先、可扩展**：先为鼠标键盘和 16:9 桌面设计；窄窗口时让侧栏折叠，不把桌面三栏硬压成不可读的小字。

### 1.1 设计边界

- 本方案不增加 GDD 未定义的资源、胜负条件、政策效果、动作成本、权限或模拟指标。
- 未实现的系统可以按本方案预留面板入口，但须显示明确的“尚未开放”状态，不呈现假数据或可点击的空操作。
- 视觉上的估算、颜色、趋势箭头与摘要均为读数的辅助表达；精确数值和单位始终可查。
- 玩家可见的数字、排序和可用动作必须来自当前权威状态与命令结果。联机客户端只提交命令并渲染，不自行推导模拟结果。

## 2. 统一视觉语言

### 2.1 主题概念：「国家档案 · 活地图」

将古典地图与行政档案的沉稳感，和现代策略游戏的清晰数据面板结合。底图像经过制图的世界图，UI 面板像国家档案中的纸页和印记；避免仿旧污渍妨碍阅读，也避免过度写实材质盖住地形信息。

| 角色 | 色值建议 | 用法 |
|---|---|---|
| 墨色 `#202A2B` | 主文字、深色栏、边框 | 主要文字对浅底保持高对比 |
| 羊皮纸 `#EEE5D2` | 面板底色 | 主信息表面；使用轻微暖色，不加噪点纹理 |
| 浅纸 `#F7F3E9` | 输入框、卡片、次级内容底 | 与主面板形成层级 |
| 青绿 `#52766B` | 已选、友好/稳定、可用动作 | 选中态同时加轮廓或图标，不能只靠颜色 |
| 铜金 `#B18A4A` | 强调、名人稀有度的高阶装饰、关键资源提示 | 节制使用，不表示成功/警告的唯一语义 |
| 砖红 `#A64E43` | 危险、拒绝、负向变化 | 同时显示文字标签/图标，避免色觉障碍误读 |
| 石蓝 `#526C83` | 信息、贸易或外交关联线 | 与地形蓝区分明度及图案 |
| 灰绿 `#8A9488` | 禁用、次要说明、未解锁 | 禁用项需说明原因，不单靠灰显 |

颜色只作为冗余编码。地形、控制权、态势等地图层须配合纹理、边线、符号或图例；正负变化还需用 `+ / −`、文字和图标表达。

### 2.2 字体、数字与图标

- 中文正文使用清晰的无衬线字体，标题可用有书卷气但笔画清晰的字体；关键数字采用等宽数字，避免刷新时跳动。
- 不把字体文件硬编码为唯一依赖。使用 Godot 系统回退字体，发布时可配置 CJK 字体；避免用字符方框拼地图图标。
- 图标统一为简洁的单色线性/实心符号，笔画粗细一致。图标旁首次出现时保留文字标签；悬停显示简短提示。
- 资源图标与色彩固定：粮（麦穗）、料（木料/石料的统一抽象堆叠图形）、器（工具/器具）、奢（宝石/饰物）、银（钱币）；具体品类与数量以 GDD 数据为准。不得靠颜色单独区分物资。
- 阶级采用稳定的图标与名称映射，跨地图图例、城镇面板、报告和名册保持一致。图标不得暗示 GDD 未定义的人物个体或职业动作。

### 2.3 字号、尺寸和密度

- 以 1440×900 桌面窗口作为排版基准，支持缩放至 1280×720；小于此范围时折叠一侧导航或切为覆盖抽屉，优先保证地图和当前详情可读。
- 正文建议 15–17 px，辅助说明不低于 13 px，面板标题 20–24 px，关键数值 22–30 px。允许系统缩放和高 DPI。
- 交互目标建议不小于 36×36 px；高频主操作建议 40–48 px。可点击格子至少有清晰悬停、选中和聚焦轮廓。
- 使用 8 px 基础间距；卡片内边距 12–16 px；面板标题、内容、脚注间距一致。
- 面板用细边线、平面色块、轻微阴影区分层级。避免大量透明玻璃效果遮挡地图。

### 2.4 动效与声音

- 选中、展开、切图层使用短促淡入/描边过渡（约 100–180 ms）；不让数值滚动动画延迟玩家读数。
- 结束回合时按阶段轻量揭示结果，允许一键跳过；动画被跳过后状态和日志完全相同。
- 重要变化使用地图标记/报告提示，不用持续闪烁。尊重系统减少动态效果设置。
- UI 音效可后续添加，默认不依赖音效提供唯一反馈；玩家可单独调节或关闭。

## 3. 主界面信息架构

### 3.1 桌面布局

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 顶栏：国家 / 年份 / 季节阶段 / AP / 五类物资摘要 / 暂停 / 设置             │
├────────────┬──────────────────────────────────────────┬───────────────────┤
│ 左侧导航   │                                          │ 右侧上下文面板    │
│ 国家总览   │                                          │ 当前格/城镇/阶级  │
│ 城镇       │              世界地图                   │ 详情与可用操作    │
│ 阶级       │      图层、图例、地图筛选与缩放          │ 因果/命令提示      │
│ 政令       │                                          │                   │
│ 名人       │                                          │                   │
├────────────┴──────────────────────────────────────────┴───────────────────┤
│ 底部操作带：当前阶段提示 / 主要操作 / 待提交命令数 / 结束回合              │
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶栏高度保持紧凑，显示当前年份（年是玩家回合单位）、当前阶段和国家级摘要；季节是结算阶段提示，不做玩家操作回合。
- 左导航默认收窄为图标+短标签，可固定展开。导航切页不清空地图选区。
- 地图占主要空间，保留缩放/平移；地图上只常驻重要边界、城镇标记和已选图层，不铺每个地块的全部数据。
- 右侧面板随选中对象切换，宽度适中，内部可滚动；详情复杂时以二级抽屉或弹层展开，避免同时打开多个互相遮挡的窗。
- 底部操作带始终明确当前可做什么、待提交命令状态和结束回合入口。若未来有多人同时回合，按玩家/回合状态显示等待或提交状态，不改变 GDD 的命令流权威规则。

### 3.2 导航分组

1. **国家**：国家总览、国库与财政、政策/政令、行政 AP。
2. **城镇**：城镇列表、单镇详情、设施和库存。
3. **社会**：阶级分布、满意度与矛盾、人口变化。
4. **名人**：候选名册、征辟/抽取、任命、执行链、诉求。
5. **关系**：外交关系；军事态势按 GDD 当前阶段显示为预留/未开放。
6. **记录**：年度报告、事件、命令记录、存档/回放入口（依版本范围开放）。

导航入口有可用内容时显示未读提示或待处理数；不显示会制造焦虑的虚假倒计时。未开放入口可在路线图范围需要时展示锁定说明。

## 4. 地图与选择交互

### 4.1 地图视觉

- 六边形单元使用细而低对比度的边线；缩放较远时弱化格线、保留国家边界和城镇位置，缩近时显示格子边界和地块符号。
- 基础地表以低饱和自然色区分水域、平原、林地、丘陵、山地等 GDD 数据地表。最终分类读取数据包，不在 UI 代码里另设地表规则。
- 河流沿六边格边绘制成连续线，不用地块填色冒充河道；湖泊和海洋有不同轮廓/纹理。流向仅在 GDD 数据可提供且图层开启时显示。
- 城镇用统一的中心符号和名称标记；规模层级仅在数据定义并实现后体现。国家/附属关系用边界和徽记表示，独立、自治、附庸、占领等状态须有明确文字/图例。
- 出生点、战略地形、门槛资源等只显示真实生成结果；未实现时不画占位假符号。

### 4.2 地图工具条与图层

地图左上工具条：缩放 +/−、适屏、当前比例；地图右上：搜索/定位（实现后）、过滤；图层选择器提供 GDD §3.9 的九种图层：

1. 地形（默认）
2. 资源
3. 人口密度
4. 阶级分布
5. 贸易网络
6. 军事态势
7. 信仰
8. 文化影响
9. 控制权

图层选择器包含当前图层名称、简洁图例、单位/范围、数据缺失说明。阶级分布等多系列图层允许选择一个阶级查看；该选择仅改变显示，不改模拟状态。尚无数据的图层标为“此版本暂不可用”，不伪造渐变值。图层应通过颜色+纹理/标记双编码，并能一键回到地形层。

### 4.3 格子拾取、悬停与选中

- 悬停：格子出现清晰细描边，短提示显示地表、坐标、关键产出/所属城镇（仅已实现字段）；延迟约 250 ms，移动出格子即关闭。
- 单击格子：选中并打开右侧地块详情；地图不因开面板而失去选中高亮。
- 双击城镇标记或点击“查看城镇”：右侧切换城镇面板；返回按钮回到该格选区。
- 再次单击空地只改变选区，不自动提交任何命令。
- 键盘方向键在相邻六边格间移动焦点；Enter 打开详情；Esc 关闭顶层抽屉或清除焦点。悬停提示不可成为唯一信息来源。
- 超出视野的定位须平移并强调目标格，禁止将格子直接跳出当前地图边界。

### 4.4 地块详情面板

建议按以下顺序呈现：

1. 地块名/轴坐标、地表类型、控制权/归属。
2. 地块三属性：产能潜力 `Y`、通行成本 `C`、防御 `D`（仅在数据可用时），显示单位和当前倍率来源。
3. 五层地块模型的摘要：地表/水文、形胜、资源标签、改良、控制权；缺数据层折叠或标“尚未生成”。
4. 邻接摘要：邻近城镇、河湖和相邻道路等已实现关系。
5. 可用命令区：由模拟/插件返回动作与拒绝理由；UI 只发送命令，不自判建城合法性。

选中非城镇空地时显示“建城”可见动作；其可用性与具体条件交给规则层判断。点按后可先呈现命令确认卡，结果由命令总线返回并显示受理、拒绝或执行结果。不要在按钮侧自行根据资源余额隐藏/拒绝动作。

## 5. 城镇、阶级与国家面板

### 5.1 城镇列表

- 可排序列：城镇名、归属/主权状态、人口、库存概览、满意度或告警（仅限已实现数据）。
- 默认排序稳定且可解释（如名称或玩家选择的列）；同值用稳定 ID 决胜，避免刷新时顺序跳动。
- 列表选择城镇时同步地图定位与右侧详情；地图选择城镇也同步列表。
- 支持搜索和按国家/主权状态过滤；不对数据做隐式聚合，所有汇总说明口径。

### 5.2 城镇详情

页签：**概览 / 阶级 / 经济 / 设施 / 关系与记录**。未实现页签显示阶段状态，不显示空白表格。

**概览**卡片顺序：城镇名与主权状态；人口总数与阶级数；五类库存及趋势；主要满意度/风险；辖地小地图或高亮；本回合变化摘要。明确“国家是政策与再分配主体、城镇是生产/消费/矛盾/人口发生地”，展示归属不能混同于城镇自身状态。

**经济**页签：

- 库存以商品行呈现：图标、名称、库存量、变动、价格（价格尚未实现时隐藏而不是造数）、本回合供需/流向（有记录时）。
- 图表默认显示最近 10 年或实际可用历史，显示单位、悬停精确值、断档说明；切换商品只换展示字段。
- 城镇内循环、国内贸易和国际贸易分区呈现，按 GDD 系统完成度逐步开放。
- 建筑设施显示等级、投入与效果来源；动作成本必须来自可验证命令预览，不在 UI 重算。

### 5.3 阶级面板

- 总览用条形/堆叠图显示八阶级人口构成；图例固定映射。未解锁阶级与人口为 0 的已知阶级需要区分。
- 每个阶级行显示：名称、人口、满意度、状态、消费/产出摘要、与其他阶级的主要矛盾轴（只显示实现且有定义的数据）。
- 选择一行展开阶级详情：满意度公式拆项（GDD §4.5 的 `满足率 + 税负 + 政策 + 信仰 + 矛盾 + 地位`），逐项显示增减与原因；不可仅显示一个最终分数。
- 矛盾按 GDD 定义的四轴和六组结构矛盾组织，先显示对总体最相关的项，再按需展开；不把“冲突强弱”包装为未经 GDD 定义的新评分。
- 鼠标悬停图表只提供精确数值和口径；同一阶级颜色在全 UI 固定，不以红绿作为唯一高低编码。

### 5.4 国家总览与 AP

国家总览突出：国名/徽记、当前年、国家归属城镇数、人口与国库摘要、治理状态、可用 AP/容量（系统实现后）、未处理报告/命令。

AP 显示为“已用 / 容量”并配进度条与超容风险说明。若命令会因超出 AP 容量而折扣执行，确认界面应明确提示预期成本/当前预算状态；最后结果必须显示实际执行率和执行链。UI 不将 AP 不足简单处理成按钮禁用，因为 GDD 规定 AP 超容是打折而非禁止。若命令验证返回拒绝，照实展示原因。

财政与政策面板只呈现规则层给出的税率、执行、支出、余额和变动来源。政策配置不直接改模拟字段，而是提交命令。

## 6. 命令与政令工作流

### 6.1 命令确认卡

所有会改变状态的玩家动作统一采用轻量确认卡或面板内确认区：

- **动作与对象**：明确命令名称、目标城镇/地块/国家/人物。
- **消耗预览**：列出命令系统提供的 AP、银、物资消耗；未提供的项显示“未提供”，不能用客户端算式填充。
- **影响摘要**：显示规则/插件提供的预期效果和不确定项；没有预览能力时写清“提交后由结算判定”。
- **提交 / 取消**：提交后记录在待处理命令列表，取消不产生模拟变化。
- **结果**：受理成功、拒绝、部分/折扣执行均显示状态、原因、实际执行率及关联日志入口。

合法性判定由命令/规则层完成。确认卡可展示拒绝理由，但不以 UI 条件替代规则校验。重复点击提交应有防重反馈，仍以命令序号/模拟结果为准。

### 6.2 年度操作与结束回合

- 顶栏常驻年份和回合阶段；意图阶段显示可提交命令，四季结算时切为只读处理状态。
- 底部主按钮文案为“结束本年”或 GDD 统一用词；若有未完成确认卡，提示玩家处理，不擅自丢弃已提交命令。
- 结束回合后进入年报。若存在关键事件，先显示摘要入口，不阻断玩家查看完整报告。
- 自动推进/连续播放未来可做为明确可关闭选项；必须允许中断到年报，默认不跳过解释。

## 7. 年度报告与因果解释（核心交互）

### 7.1 年报结构

年报作为回合结算后的主页面，顶部有“第 N 年 · 年度报告”和返回地图按钮。采用“摘要 → 变化 → 原因 → 后续待办”的阅读顺序：

1. **年度摘要**：最多 3–5 条关键变化，以结果和对象命名（例如“北境粮库存下降”），标出正向/负向/中性。
2. **国家概览**：人口、城镇、财政、可用 AP、重大关系等有数据的指标，对比上一年；没有数据不占位。
3. **城镇变化**：按影响程度或用户排序显示，可过滤城镇、类别和正负变化。
4. **阶级反应**：满意度变化及拆项；指出哪个因素上升/下降、对应城镇/阶级。
5. **政令与名人执行**：命令结果、执行率、官员/任命者参与的执行链和未执行原因。
6. **事件与抽取**：本年度事件、卡池结果、概率/保底信息入口（若发生或系统已实现）。
7. **未决事项**：来自系统的可处理命令或待审阅信息，不自动替玩家决策。

### 7.2 因果链展开

每条重要数字变化都能展开为：

```text
结果：白石城粮价 +18%
公式：p' = …（由模拟记录提供）
各项：需求 … / 供给 … / 系数 …（使用结算已算出的值）
原因：歉收、征粮等已记录原因（可点击定位关联事件/城镇/命令）
```

采用分层展开：摘要行 → 公式及因子 → 来源事件/命令/因果父项。展开不重新跑规则、不重新计算公式，只格式化并展示记录的结果、公式说明、值和 `reason`。缺少因果记录时明确显示“当前没有可展开的来源”，作为数据缺口呈现，不编造解释。

变化箭头旁同时显示绝对值与相对值（如两者均可得），避免只用百分比掩盖小基数。每个数值标注单位、对象和时间区间。排序默认把影响大的置顶，但排序规则可见，用户可切换按城镇/类别/时间排序。

### 7.3 报告到地图的联动

- 点击报告中的城镇、地块或关系线，关闭/缩小报告到侧栏并定位地图；原报告滚动位置保留。
- 地图闪亮强调只做短暂一次，不持续闪烁；相同变化关联多个对象时可逐项跳转。
- 年报支持“全部标记已读”，但阅读状态不得改模拟状态或哈希。

## 8. 名人、卡池与执行链

### 8.1 名人名册

- 列表卡片包含姓名、所属城镇/阶级、稀有度、四维能力、已知特质、当前职位/状态（均以 GDD 数据字段为准）。
- 正负特质使用中性且一致的图标标记，负面效果同样可查看，不把高稀有度表达成必然最优。
- 选择人物后展示详情页：能力、特质影响、诉求、人际关系（系统逐项实现后开放）、历史任命和执行记录。
- 任命流程通过目标职位/城镇选择和命令确认提交；职位资格及执行条件由规则层返回。

### 8.2 征辟/抽取界面

- 抽取前展示消耗、候选池主题、当前概率权重和保底组进度；概率可查看是强制信息，不藏在帮助页。
- 候选卡按相同模板比较，清晰区分已知信息与未知信息；三选一流程按 GDD 执行，不添加刷新、重抽等未定义操作。
- 抽取结果页列出候选、入选者、所属阶级/城镇、稀有度及其可关联的职位/玩法入口；不做赌博式强闪或伪造概率承诺。
- 概率、权重、保底进度来自当前卡池状态，显示取值口径和适用范围；客户端不自行估算。

### 8.3 执行链

执行链是本作的招牌组件，采用纵向时间线：

```text
玩家政令 → 命令校验/AP → 受命官员 → 官员判断/执行率 → 城镇结果 → 状态变化
```

只展示模拟记录实际提供的节点。节点显示责任主体、阶段、输入/结果、执行率和原因；被驳回/折扣/改变目标等状态使用文字+图标。点击某节点可打开对应人物、城镇、命令或因果详情。未经过的人物/阶段不补画成确定事实。

## 10. 空态、错误和反馈状态

所有核心面板均定义以下状态，且沿用相同提示位置和视觉语言：

- **加载/结算中**：说明正在读取或处理哪一阶段；避免无限旋转且无文本。模拟不可交互时清楚标注。
- **空状态**：说明为什么没有项目以及下一步入口，例如尚无城镇、尚未解锁阶级；不能用“暂无数据”掩盖程序错误。
- **锁定/未实现**：标明是未解锁、当前版本未实现还是权限不足，三者文案不可混淆。
- **命令受理**：显示已进入命令流/等待结算，不误报为最终成功。
- **命令拒绝**：显示规则返回的原因、目标和可查看详情；不只显示红色叉号。
- **部分或折扣执行**：显示实际执行率、已执行结果与未达成部分的解释。
- **错误/断线**：保留玩家正在查看的上下文和未提交编辑；联机时明确最后确认回合和重连状态。
- **过期数据**：明确标出数据对应回合；提交后若权威状态已变化，提示刷新/重新确认，不静默覆盖。

提示语使用直接、具体、无责备的中文。示例：“命令已受理，将在本年结算”“行政容量不足，本条命令按 62% 执行”“此图层的数据尚未开放”。百分比及原因必须为真实记录值。

## 11. 无障碍与操作方式

- 所有按钮、选择器和地图格子都可通过键盘聚焦；提供可见焦点环和合理 Tab 顺序。
- 常用动作配置明确快捷键提示（如 Esc 返回、Enter 确认）；快捷键可查看，避免与文字输入冲突。
- 不用颜色作为唯一状态提示；支持高对比度方案并检查色觉差异下的地图图层辨识。
- 界面缩放不裁切关键数值；文本不以图片呈现；图表提供可读表格/悬停精确值替代方案。
- 动效可减少；重要确认不只依赖声音，声音关闭不影响反馈。
- 对地图格子的键盘焦点使用高对比描边+坐标提示；屏幕阅读器接入作为后续可访问性工作，交互组件应保留语义标签。

## 13. 和实现架构的约束

- UI 只读模拟状态、报告和命令结果；通过统一命令接口提交操作。不在 Godot 控件回调中写玩法判定或计算公式。
- 显示层复用报告中已算出的值和原因。禁止为了显示百分比、比较值或解释文本，在 UI 重新计算模拟公式。
- 视觉动画、排序、筛选和阅读状态不得写入模拟世界，不得影响确定性哈希。
- UI 插件按 GDD `ui.*` 面板边界拆分；面板之间通过公开状态/命令接口协作，不直接调用其他规则插件。
- 地图图层为纯查询与渲染；切换图层不得修改世界状态。
- UI 设计稿的假数据必须醒目标记为示意，并且不得进入游戏数据包或自动化基线。

> 规则或字段缺口请提交到 `CHANGELOG-DESIGN.md` 待裁决；视觉方案本身不能替 GDD 作规则决定。
