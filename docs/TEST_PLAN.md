## 0. 一分钟版

```bash
dotnet build                # TreatWarningsAsErrors：警告就是错误
dotnet test                 # 59 条，约 1.5 秒
dotnet run --project src/HexaCiv.Cli -- check                    # 数据包 + 插件清单
dotnet run --project src/HexaCiv.Cli -- hash   --seed 99 --turns 50
dotnet run --project src/HexaCiv.Cli -- replay --seed 5  --turns 20 --at 12
dotnet run --project src/HexaCiv.Cli -- run    --seed 42 --turns 200 --headless --out analysis/out/demo.csv
```

前两条是「提交前必跑」。后四条里 `check` / `hash` / `replay` 是 §10.8 的三类自检，
最后一条是 §10.8 末行要求随里程碑提交的**基线模拟报告**。

**这套测试管的是「这台机器能不能被相信」，不管「好不好玩」。**
数值轨迹的判读在 `docs/BALANCE.md`，那里的数字一个都不进断言。

## 2. 59 条的分层清单

### `FixTests.cs`（12 条）· 定点数本体

`刻度与构造` / `负数乘法不误报溢出` / `除法向零截断且负零不出现` / `取整三种语义各自正确` /
`区间限制按附录A的写法` / `定点值的规范文本可无损往返`（Theory，7 个样本，含 `long.MinValue`）。
挂了 ⇒ 一切数字都不可信，先修这里，别往下读。

`负数乘法不误报溢出` 与 `取整三种语义` 各挡一个真实踩过的坑：
`Fix.Mul` 走 `UInt128` 中间量（`Fix.cs:72`），符号单独记——因为 net8 没有 `Int126`，
而「先把负数升成 UInt128 再取负」会得出 2^128 级别的天文数字（`Fix.cs:84-98` 的注释记了全过程）。

### `RngTests.cs`（10 条）· 分层随机（§8.3）

同种子同命名空间必相同 · 换命名空间不得影响另一条流 · 换种子必须换序列 ·
同工厂内重复请求同一命名空间拿到同一条流 · `OneShot` 不吃缓存也不喂缓存 ·
取值范围与边界 · 加权抽取尊重零权重且可复现 · 正态扰动均值为零且离散度等于标称标准差 ·
回合边界重置命名空间流缓存 · 全局流状态可存可取。

`回合边界重置命名空间流缓存` 是 §8.3 纪律 1（命名空间必须自带回合号）的执法者：
任何规则想「依赖上一回合的流状态」，它立刻红。

### `OrderAndDataTests.cs`（10 条）· 内核契约

结算表 = GDD 那张表（15 步的 id/标题/季节/hook 逐条比）· 四季分布与意图段 ·
**首尾同名的步必须靠 slot 区分** · 每个 hook 点都说得出落在哪（21 个点）·
合法数据包按 id 序数返回且哈希稳定 · 严格模式拒收坏数据 · 清单有问题就拒载 ·
依赖决定装载顺序且禁止成环 · **清单键名拼错就拒载而不是静默落回默认值** · 仓库里真的装着 core.basic。

后两条是 2026-11-13 补的：`manifest.json` 曾把 `load_priority` 写成 camelCase，
`System.Text.Json` 一声不响地落回默认值 0——优先级、数据包开关这类字段静默失效，
比崩溃难查一个数量级。现在未知键（`@` 前缀的注释键除外）直接拒载。

### `CoreBasicTests.cs`（14 条）· 规则语义

建城即有人有仓底有辖地 · 自动选址只会挑可建城的地块 · 驳回理由要说人话而不是抛异常 ·
两城之间至少隔 3 格且辖地不重叠 · **产出等于公式一的两个上限取小** · 没有人口绝不出粮 ·
农田折进设施系数且封顶 1_45 · 粮仓同时加仓容与降损耗 · 存粮永远不超过仓容 ·
丰年人口靠零头攒着往上涨 · **缺粮但不至于饿死时零头桶照样在涨** · 灾年先断粮再减员最后反抗 ·
满意度向S星收敛且只吃口粮一项 · 国势栏是各城的合计而不是又扫一遍世界。

这批里最要紧的设计是 `产出等于公式一的两个上限取小` 与 `满意度向S星收敛且只吃口粮一项`：
它们在测试里把 GDD 的公式**重新算了一遍**。实现与文档各写一次、结果必须撞在一起，
这才叫「贴着附录 A 写代码」被机器看着——只断言一个手抄的期望值是拦不住公式改形的。

### `AcceptanceTests.cs`（13 条）· §12 里程碑验收

空世界跑一千回合不崩（M0）· 同种子同命令流_逐回合哈希位级相同（M1）· 换种子必须换世界 ·
少一条命令就该分叉 · 命令被拒也要留下记录而不是静悄悄 · 第K回合的档加后面的命令等于一口气跑满 ·
读回来的档能改能跑且 kind 计数器续得上 · 坏档不得覆盖最后一个有效存档 ·
存档负载不带 BOM 且带 BOM 的明文档也读得动 · 非法状态在结算里被抓住而不是悄悄跑下去 ·
宽容模式下同样的坏只记录不抛 · 每一次数值变化都带着理由 · 年报里的数字能对上世界状态。

`少一条命令就该分叉` 是反向断言：删掉一条命令后哈希**必须**变。
它挡住的是「命令流其实没参与结算」这类伪装成通过的通过。

## 3. 跨宿主一致性（不跑在 `dotnet test` 里的那一条）

§10.6 的回放与 §10.7 的确定性只有在**两个宿主都给同一个哈希**时才算立住：
CLI 跑在 .NET SDK 的默认 `AssemblyLoadContext`，Godot 跑在它自己的脚本上下文，
插件两边都是从 `build/plugins` 的 dll 装载的。

```bash
dotnet build                                                        # 必须先 build：Godot 读的是 build/plugins 的产物
dotnet run --project src/HexaCiv.Cli -- hash --seed 7 --turns 6 --script scripts/godot-smoke.txt
godot --headless --path src/GodotShell -- --smoke                   # 或用 mono 版编辑器可执行文件
```

两边都必须给出末回合哈希 `3c72a09ae26803e9`（`scripts/godot-smoke.txt` 与 `src/GodotShell/Main.cs` 的
`Smoke()` 提交的命令**逐字相同**，改一边就要改另一边，否则这条比对立刻红）。
Godot 侧还顺带验渲染：`smoke 拾取：183/183 命中`、字体回退、`SMOKE PASS`。

**这个比对目前没有自动化**——它需要一个能跑 Godot 的 CI runner（§6）。

## 4. 加一条测试的规矩

1. **钉公式，不钉基线数字**。轨迹数字（人口、粮产、满意度）属于 `docs/BALANCE.md`，
   进断言就等于把标定结果冻结成回归门槛，下次改数全红。
   要钉就钉「min 的两个上限取小」「S\* = 50 + 60(s−e)」「仓容 = 人口×2 + 粮仓×20」这种**关系**。
2. **新公式必须配一条反向用例**：把它的输入推到 0、推到越界、推到不该触发的分支，
   断言它**不**动（`没有人口绝不出粮` 就是这个套路）。
3. **失败消息要能自证**。写`s = 0.60 时零头桶只加了 0.00：0.04·粮安 被 1/100 刻度截成 0`，
   而不是 `Assert.True(false)`——读消息的人（可能是下一个 AI）应该不用重新推导就知道发生了什么。
4. **确定性优先于覆盖率**。任何用到 `Rng`、字典遍历、`DateTime`、`float` 的新代码，
   先加一条「同种子跑两遍」的用例，再谈别的。§10.7 的纪律靠测试执法，不靠自觉。
5. 断言世界状态用 `sim.World.Get*`，断言**变更**用 `TurnReport.Diffs`（`Diff` 是
   `readonly record struct`，字段 `Turn/Step/Id/Path/Before/After/Op/Reason`，见 `src/SimCore/Mutation.cs:17`）。
   年末现值和当年日志不是一回事：同一回合的第 10/12 步还会继续改字段。

## 5. 性能与规模剖面

| 场景 | 现在 | 门槛来源 |
|---|---|---|
| 空世界（无插件无数据）1000 回合 | 3.7 s 含进程启动 | §12 M0 验收「不崩」 |
| 1 城镇 200 年（538 字段） | 后 100 回合均值 **1.491 ms/回合** | `--headless --out` 的 `ms` 列 |
| 2 城镇 200 年（572 字段） | 同区间 **1.692 ms/回合** | 同上 |
| 500 城镇 × 200 回合 | ⛪ 没测过，也铺不出来（M1 建城要国库出粮、要 ≥3 格间距） | §10.8 / §14「> 60 秒即降级聚合粒度」，**M4 前必须做** |

两条实测的差给出 M1 的成本结构：**固定开销 ≈ 1.29 ms/回合，每城边际 ≈ 0.20 ms/回合**。
按它外推 500 城 × 200 回合 ≈ (1.29 + 500 × 0.20) × 200 ≈ **20 秒**，还在 60 秒线内。

但这个外推只能用来定基线，不能用来安心：0.20 ms 是**每城只挂 4 个处理器**
（`Facilities`/`Produce`/`Consume`/`Satisfaction`/`Demography` 里除去全局那几个）的成本，
按 §12 的交付，M4–M9 每城的处理器数量至少翻 4–5 倍，同一外推就落到 80–100 秒。
所以 §14 的「阶级聚合降级路径」不是理论预案。**剖面要在 M4 之前建立，别等到踩线那天才开始量。**
工具已经在了：`sim run --steps` 打 15 步的分步耗时，`--out` 的 `ms`/`fields` 两列就是曲线。

## 6. CI：M0 唯一没兑现的验收项

`.github/` 目前是空的。§12 M0 的三条验收里「CI（单测 + headless）」因此没过，
`docs/ROADMAP.md` §2.1 把 M0 标成 🟡 而不是 ✅。要补的工作流应当只有三个 job：

| job | 步骤 | 挂了意味着 |
|---|---|---|
| `build-test` | `dotnet build` + `dotnet test` | 单元/契约/验收任一红。注意 `Directory.Build.props` 里 `TreatWarningsAsErrors=true`，警告也算红 |
| `sim-headless` | `sim check` → `sim hash --seed 99 --turns 50` → `sim replay --seed 5 --turns 20 --at 12` → `sim run --seed 42 --turns 200 --headless --out` 并上传报告 | 确定性、回放等价、或基线报告无法生成 |
| `godot-smoke` | `godot --headless --path src/GodotShell -- --smoke`，比对 `3c72a09ae26803e9` | 跨宿主分叉（§3），或渲染/拾取崩了 |

三个 job 都该跑在 **ubuntu + windows 两个矩阵**上：§10.7 的位级确定性最怕的就是
只在开发机上验过。CI 里第一个 Linux 绿的哈希必须当场抄进 `docs/BALANCE.md` §4 与 `CHANGELOG-DESIGN.md`，
之后它就是基线。**在此之前，「跨平台一致」是一个尚未验证的假设，不是已完成的事实。**

## 7. 已知没测到的东西

- **跨平台哈希**：只在 Windows 上比对过（CLI ↔ Godot 两个宿主，同一台机器、同一种 CPU/OS）。
- **三条守恒等式**（§5.9 前三条）：M1 没有进出口与迁移，等式两边恒等，写了也测不出东西；M3 接公式二时一起补。
- **`GodotShell` 的渲染像素**：只验拾取命中与不崩，没有截图比对。
- **热加载与创意工坊**：插件宿主在 M11 之前没有「运行中换 dll」路径，未测。
- **多插件相互影响**：现在只有一个 `core.basic`，`load_priority` 与依赖排序只有单测层面的覆盖
  （`OrderAndDataTests.依赖决定装载顺序且禁止成环` 用假插件跑），没有真实的双插件场景。
